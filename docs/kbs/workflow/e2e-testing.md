# End-to-end testing

- Code: `scripts/e2e.ts`, `e2e/support/groups.ts`, `playwright.config.ts`, `apps/api/src/db/e2e-worker-seed.ts`, `apps/api/src/db/e2e-leak-check.ts`, `apps/api/src/db/test-fixtures.ts` (`smallFixtureCopy`), `e2e/support/export-fixture.ts`.
- Every `test:e2e*` command goes through `scripts/e2e.ts`: build the web bundle once, run a parallel group (`fullyParallel`), then ~~a serial group on one worker~~ *(2026-11-09, chore T3: the `queue` lane on `QUEUE_WORKERS` = 2 workers, `fullyParallel`, then the `solo` lane on one worker)* (`SERIAL_SPECS` in `e2e/support/groups.ts`, each entry naming its lane: ~~specs sharing the document queue, LibreOffice or a fixed-id fixture, and every spec that times a tap against a render;~~ *(2026-11-09: `queue` holds the specs sharing the document queue and LibreOffice, the reading queue or a held generate request, `solo` every spec that times a tap or a wait against a render;)* a `test:unit` guard in `scripts/e2e.test.ts` fails any e2e source, but `support/sync.ts` and the production smoke, whose `data-pending` wait carries a timeout from 30 s or a constant, the 60 s tick decision C-4 replaces with `syncNow`; it reads that badge wait only, not outbox polls, chore T2 2026-11-04). ~~Both groups always run; the command fails if either fails.~~ *(2026-11-09: the three runs always all run, in the order parallel, queue, solo; the command fails if any fails, and the global setup refuses a run with more workers than its lane allows: `queue` 2, `solo` and a bare `playwright test` 1, `E2E_GROUP=serial` is no longer a name.)* Since the 2026-10-08 gate-integrity batch (TST-V1) it also fails when a spec path it was given ran no test in either group (a typo, a spec whose every test skipped, a `:line` no test or describe starts on; option values are read as Playwright's own parser reads them, so `--update-snapshots all` or `--project a b` never become paths), and `playwright.config.ts` sets `forbidOnly: true` (with `allowOnly: false` in every Vitest project and `eslint-plugin-playwright` `no-focused-test` and `missing-playwright-await` as errors on `e2e/**`, `no-wait-for-timeout` as a warning outside a two-file allow-list), so a stray `.only` or a mistyped path can no longer pass the gate on fewer tests.
- Tags: `@p0` is the merge gate; `test:e2e:full` runs everything regardless of tag; `test:e2e:matrix` runs the durability suite on desktop Chrome, Android Chrome emulation and WebKit. ~~Only the epic retro runs full and matrix.~~ *(2026-11-04: since E10-A1 and E11-A1, `@p0`, full and the full matrix run once per wave on the integrated main, launched by the coordinator, and at the epic QA; a story PR runs its touched specs, [merge-gate](/workflow/merge-gate.md).)*
- Parallel workers: default `PARALLEL_WORKERS` is ~~1 (three-worker validation still failed, `spec-test-speed.md`)~~ 2 since 2026-10-08 (two green `@p0` runs at 612 s and 723 s against 1081 s on one worker; corrected here 2026-11-04, chore T2); `--workers=N` overrides for one run. Each worker has its own pair of companies (`workerSeed(index)` in `apps/api/src/db/e2e-worker-seed.ts`); a global teardown leak check fails the run if a worker wrote outside its pair.
- Small Porto Seguro fixture in e2e (chore T3, 2026-11-09): `resetEmpresaBWithFixture(b)` seeds this worker's Empresa B with its own copy (`smallFixtureCopy(companyId)`: relatório, project, block, cabine, equipment and op ids derived from the company with an `e2e-copy:` salt, never the fixed ids nor the developer sample's) and returns it; a spec takes every fixture id from that copy, and a `test:unit` guard fails any e2e file naming `EXPORT_RELATORIO_ID` or importing the fixture's constants. The api suite's `TEST_SEED` companies keep the fixed ids.
- Timeouts: actions 15 s, navigations 30 s. Output: `test-results/e2e-report/summary.json` and `timings-{group}.json` ~~(`parallel`, `serial`)~~ *(2026-11-09: one per lane, `parallel`, `queue`, `solo`)*.
- Nothing ships untested. A feature with a front end runs through Playwright as a human would, covering the whole feature. In addition the owner wants a hands-on pass via the Playwright MCP browser at 390, 768 and 1280 px with screenshots saved under `_bmad-output/implementation-artifacts/reviews/`.
