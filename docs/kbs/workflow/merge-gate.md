# Merge gate

- Command on a shared machine: `flock /tmp/fasor-verify.lock docker compose --profile tools run --rm tools pnpm verify`; paste its output in the PR. Budget under 15 minutes. Source: `scripts/verify.ts`.
- `verify` runs three phases: (`lint`, `static`, `test:api`) together, then `test:unit` alone, then `test:e2e` (Playwright `@p0` on `desktop-chrome` and `durability-desktop-chrome`) alone. First failure stops its phase and later ones. Logs: `test-results/verify/`. `test:unit` has no database access; `test:api` uses compose Postgres and MinIO.
- **api suite lanes (2026-11-26, chore T4, `sprint-change-proposal-2026-11-04.md` § 4.5)**: `test:api` (`scripts/api-suite.ts`) runs the four Vitest projects of `apps/api/vitest.config.ts` (`apps/api/src/test-lanes.ts`, each listed file with its reason) in two phases: first `api-solo` alone, then `api` on `PARALLEL_WORKERS` workers, each on its own `TEST_SEED` pair (`testSeedPair` in `apps/api/src/db/test-seed.ts`; pair 1 is the fixed `a@teste.local`/`b@teste.local` pair, worker slot `k` gets pair `k + 1` through `API_TEST_PAIR`), beside one Vitest run of `api-serial` then `api-print`, one file at a time on the fixed pair. Every lane always runs; logs in `test-results/api-suite/`. `pnpm test:api` runs all four (wave gate, `verify`). The batch gate runs `pnpm test:api:batch` with `API_CHANGED_FILES` filled on the host from git (command in AGENTS.md "Running and verifying"); it leaves `api-print` out only when no changed path is under `PRINT_TRIGGERS`, and runs it when the list is unset or empty. Guards in `scripts/api-suite.test.ts`: a test file reaching the document queue, the fixed-id fixture, a layout-lock fixture in the database, a fixture op reclaim, the seed CLI's `--test` or a golden cannot sit in the parallel lane, a legacy company or a boot upgrade must sit in `api-solo`, and the print's import closure must lie under `PRINT_TRIGGERS`. `API_PARALLEL_WORKERS=N` resizes the parallel lane for one run. Measured times: `_bmad-output/implementation-artifacts/spec-t4-api-suite-speed.md`.
- **Split gate (decided 2026-09-30)**: a story PR runs `verify` plus the specs it touched, plus the durability specs on `test:e2e:matrix` when it changes the op fold, the commit path or a live query on the ficha. `test:e2e:full` and the full matrix run once per wave on integrated main and at epic QA.
- **Story gate (decided 2026-10-08, E11-A1; amends the split gate)**: a story PR runs `lint`, `static`, `test:unit`, `test:api` and the Playwright specs it touched (plus touched durability specs on the matrix projects under the same condition); the full `@p0`, `test:e2e:full` and the matrix run once per wave on integrated main. Load rules: at most two batch stacks up, no Playwright outside the lock, main checkout stack stopped while batches run. On the macOS podman host: `podman compose`, `lockf` instead of `flock`; since 2026-10-08 the plain `pnpm verify` fits the 11.4 GB VM again and the `@p0` parallel group runs on two workers. Source: AGENTS.md Decisions of record; `epic-batch-orchestrator.md`.
- **Gate preflight (2026-10-15, Story 14.10 part 1)**: `pnpm verify`, each stage run alone (`lint`, `static`, `test:unit`, `test:api`) and `scripts/e2e.ts` first run `scripts/preflight.ts`. It reads the compose project's containers through the engine socket the `tools` service mounts (`/var/run/engine.sock`, GET requests only) and exits 1 within 15 s with `preflight: <container> is restarting (restarts: N); last log: <line>` when a container restarts in a loop; no socket or an engine error is one line and the gate goes on. `verify` passes `GATE_PREFLIGHT_DONE=1` to its stages so the probe runs once. Source: `scripts/preflight.ts`, `docker-compose.yml`.
- Never merge on a red or partial verify, even for flakes.
- On a shared machine one gate at a time: wrap `verify`, `test:e2e:full`, `test:e2e:matrix` and multi-worker runs in `flock /tmp/fasor-verify.lock`.
- `pnpm audit --prod` is not part of verify; its known advisory is tracked in `_bmad-output/implementation-artifacts/deferred-work.md`.
- The production smoke (`e2e/production/*.smoke.ts`, `pnpm smoke:production`, 2026-10-15) is not part of `verify`, the story gate or any `test:e2e*` command; the root Playwright config never collects it (`scripts/e2e.test.ts`). Only `infra/bin/deploy` runs it, after a deploy.
- **Gate record before a deploy (2026-11-03, E18-A6)**: before `infra/bin/deploy` of an integrated main, `test:e2e:full` is green on that commit under the host lock, with the host load line (`sysctl -n vm.loadavg` at start and end, lock wait, what else ran), recorded in `epic-<N>-context.md`; `verify` alone does not count (no `@p1`/`@p2`). Source: `infra/PUBLISHING.md` § Every publish step 1; playbook § 8. Since 2026-11-04 (E20-A4, playbook § 9) the deploy record also lists every open `deferred-work.md` row marked "before the deploy" with its result.
- **One-off direct push (2026-11-04, Matheus, not a standing rule)**: two test-only fixes (`8dda538c`, `aa5bfff2`) went to main with no story or PR after their touched specs passed; everything after them goes through a branch and a PR. Source: `AGENTS.md` decisions of record, `sprint-change-proposal-2026-11-04.md`.
- **Tools as node (2026-11-25, Story 30.2 D, tools-root E26-A8)**: the gate runs `podman compose --profile tools run --rm --user node tools ...`; `docker-compose.yml` adds the engine socket's group to `tools` (`group_add`, `ENGINE_SOCKET_GID`, default 0), which root was used for. `scripts/preflight.ts` first fails naming any root-owned entry of the four `node_modules` volumes (each `.vite-temp` first, then two levels of each volume), then probes the containers as before.
- No CI. AWS Budget and deploy are separate: [infra-aws](/architecture/infra-aws.md).
