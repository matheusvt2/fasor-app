# Data model

- **Ownership (AD-5)**: Company owns users, Templates, Projects and registries (Empresa, Clients, Instruments, Manufacturers, Voltage classes, Atividades, Locais, Criteria). Project = client plus site (Site collapsed into Project) and owns Equipment `{id, project_id, tag, type, last_nameplate?, removed_at?}`. Relatório owns its Location tree, blocks, sheet values, photos, points, suggestions, generation jobs, revisions, `export.scheme`. Creation is one client batch from `instantiateTemplate`; the server never copies a Template. A company- or project-scope row never references a relatório-scope row.
- **Location (AD-6)**: `{id, relatorio_id, parent_id?, kind cabine|coluna, name, order_key, se?, env?, agrupar_por_tipo?, removed_at?}`; `se`, `env`, `agrupar_por_tipo` only on `kind = cabine`. "First sheet" of a cabine is computed (`firstInTree`), never stored. `feeds_block_id` pairs a cabos-de-saída block to its transformer; `groupForPrint` pairs only by it. *(2026-10-08, AD-6 amended: the coluna is optional ~~and on screen a cabine is a "local"~~ (~~2026-10-09: decided Local › Cabine › Coluna — `kind local|cabine|coluna`~~ 2026-10-10: Local › Painel › Coluna — `kind cabine|painel|coluna`, the root cabine is the "local" on screen, keeps `se`/`env`/`agrupar_por_tipo`, gains `funcao` and carries the site `checklist`; a painel only groups colunas; older cabine › coluna rows stay valid); a cabine gains `checklist` (Verificações do local, family `location/{id}/checklist/{itemKey}/{result|observation}`, seed v4); a point may carry `location_id`.)* *(2026-10-13, Story 14.2 as built: `funcao` is a string written only through `location/{id}/funcao`, a reserved key (`entrada|primaria|transformacao|distribuicao`) or a typed name of at most 80 characters, optional on stored rows (absent or null before contract 17, no migration); a `painel` row is `{id, relatorio_id, parent_id, kind: painel, name, order_key}` and holds no data and no block; a coluna hangs under a painel or, as before, under a cabine. `applyOp` throws `LocationKindError` for what a kind never holds (a `funcao` put off a cabine, `se`/`env`/`agrupar_por_tipo` on a painel, a block placed on a painel held in state); the Template skeleton carries the same three node kinds and the `funcao`. Code: `relatorio/local.ts` (`funcaoLabel`, `defaultLocalName`, `takesBlocks`), `relatorio/tree.ts` (three levels), `templates/compose.ts` (`addPainel`, `setFuncao`).)* *(2026-10-13, Story 14.2 second pass: a coluna, a painel and a local can be removed and restored in the relatório tree, with no new op path (contract 17). A removal is one batch of `location/{id}/removed_at`, `block/{id}/removed_at` and `equipment/{id}/removed_at` removes planned by `locationRemovalPlan`; all its rows share one `removed_at` (the batch's `client_ts`), which is how a restore tells them from an earlier removal. A location is live only when its own row and every row above it are not removed (`liveLocationIds`); both snapshot builders drop a location that is not live and a block whose location is in the state and not live, so a sheet another device left under a removed location is hidden with it. `locationRestorePlan` brings back the location, what left with it and the removed rows above it; `restorableEntries` lists a removed location only while its parent is live and a removed sheet only while its location is live. Code: `relatorio/location-live.ts`, `relatorio/removal.ts` (plans and their texts), `relatorio/sumario.ts` (`restorableEntries`), `relatorio/tree.ts` (`locationControlName`: a coluna's controls are named with its painel and local). Open points: `deferred-work.md`, Story 14.2 entries (g) to (k).)*
- **Sheet state (AD-18)**: `not_tested != null` -> Não ensaiada; else `concluded_by != null` -> Concluída (kept through edits; `integrity` flags "concluída com pendências"); else any non-empty enabled cell -> Em preenchimento; else Vazia. Attribution fields are materialized by `applyOp`, never emitted. Values in a disabled sub-block are kept but ignored by progress, pre-issue, conclusion, integrity, counts and renderer.
- **Registries (AD-19)**: Clients and Instruments by id; selecting an instrument copies its whole header onto the sheet at that moment (`calibrationCheck` compares `valid_until` with the service period end, expiring within 30 days). Manufacturer, Voltage class, Atividade, Local are stored by value; registries are suggestion lists deduplicated server-side by normalized name.
- **Equipment (AD-25)**: `equipment/*` ops are project scope and reach every relatório stream of the project. Uniqueness of `(project_id, tag)` is a kernel `integrity` check, not a DB constraint. `equipment/{id}/last_nameplate` is a `system:generate` op emitted when a revision is stored; "Copiar da última visita" reads it from Dexie and never fetches.

Code: schemas `packages/domain/src/schemas/`; logic `packages/domain/src/relatorio/` (`ficha.ts`, `cabine.ts`, `instantiate.ts`, `integrity.ts`, `progress.ts`, `tag.ts`, `move.ts`), `registry/`, `registration.ts`, `checks/calibration.ts`, `print/last-nameplate.ts`; server tables `apps/api/src/db/schema.ts` with `repositories/`.
