# Kernel, contract, seed

**AD-2, exists once in `packages/domain`**: `applyOp`, `mergePolicy`, `integrity`, `preIssue` (its rows are also the Sumário row statuses), `progress`, `sheetState`, `syncCounts`, `editedSince`, `instantiateTemplate`, `suggestConclusionPair`, `composeConclusion`, `suggestParecer`, `composeParecer`, `suggestTag`, `suggestNameplateCopy`, `compareSuggestion`, `parse`, `format`, `deadlineFromPriority`, `contextCaption`, `section11Instruments`, `calibrationCheck`, `groupForPrint`, `numberPhotos`, `extractPhotoRefs`, `resolveSection8`, `derivedPoints`, `statusTable`. If a task needs a status, count, text, order or verdict, extend this set. One integration test asserts the Sumário rows (Dexie) and the pre-issue list (Postgres) are identical for the Porto Seguro fixture.

**AD-11 field kinds**: every nameplate, SE and measurement field has `kind` in text, number, date, select, manufacturer, voltage_class. A number is `{raw: "3300", unit, state: measured|not_measured|empty}`, `raw` a decimal string with `.`; dates are ISO `YYYY-MM-DD` or `YYYY-MM`. pt-BR parsing (comma decimal, point thousands, `147G`) lives only in `domain/src/parse`; output formatting only in `domain/src/format`. No floats in storage. Derived cells (VAL CALCULADO) are never typed.

**AD-13 contract**: the client talks to the server only through routes typed in `packages/domain/src/contract` (zod request/response, `CONTRACT_VERSION` header): sync ops and pulls, file PUT/GET, generate, preview, reread, revisions download, auth, health. Error envelope `{code, message, details?}`; routes and families are append-only.

**AD-21 seed**: `BlockConfig = {block_type, subtype?, role?, sub_blocks, na_defaults}` is the only thing copied into a Block row, with a `seed_version`. Field definitions, checklists, table grammars, criteria, not-tested reasons and section boilerplate resolve through `getDefinition(seed_version, report_type, block_type)`; `packages/domain/src/seed` (v1, v2, v3...) is append-only so every shipped version still resolves. A criterion needs operator, value, unit, type and source. Source of truth for the seed is the decoded FO.SERV-03, not the UX counts. *(2026-10-08: an amendment is proposed for office-created company equipment types beside the seeded eight — immutable published versions, a resolver context in `getDefinition`, a generic measurement table; settled by `bmad-architecture` before Story 14.6 (renumbered 2026-10-09; Story 14.5 first ships the measurement table and ~~two library types~~ one library type (2026-10-13; the second was dropped on 2026-10-10) as seed v5). Seed v4 adds the site checklist list, Story 14.3.)*

*(2026-10-13, Story 14.5 as built: `SEED_VERSION` is `v5`, v4 plus one library type, `chave_transferencia_automatica`, on a generic measurement-table grammar; `BlockConfig` gains the optional `options` (a type's own configuration); the closed type enum holds nine keys, and a type is offered only by the seed versions that define it (`equipmentTypesOf(seedVersion)`), so "the seeded eight" reads as eight on v1 to v4 and nine on v5; `getDefinition` throws for a type its version lacks. `CONTRACT_VERSION` and `MIN_CONTRACT_VERSION` are 19. No company-type machinery was built. See [measurement-table](/architecture/measurement-table.md).)*

**AD-22 status table**: `packages/domain/src/status` holds `(state, event) -> state`; every transition is a client op on `relatorio/status`, the server never writes it. Table of 2026-10-10 (Matheus, source-deltas): Rascunho -setup_complete-> Em campo; Rascunho -edit-> Em campo for field content only (`countsAsFieldContent` in `status/edited-since.ts`: a sheet value, a sheet concluded or not tested, a cabine's SE and ambiente fields, a photo, a point; structure, a block's config and `relatorio/setup` keep Rascunho); Rascunho or Em campo -generate-> Em revisão; Em revisão -issue-> Emitido, emitted only by "Marcar como enviado ao cliente" (never by a revision's arrival) and offered while nothing was edited since the latest revision; an edit in the `editedSince` family set moves Emitido back to Em revisão. Em revisão means a revision was generated and not yet sent. `relatorio/status-advance.ts` holds the edit emitter (`advanceOnEdit`) and every status sentence (banners, `statusChangeToastText`); `relatorio/sumario.ts` the next-step sentence drawn under the Sumário's status pill (`statusStepText`), `canMarkSent` and the Controle row line ("Rev. N gerada" until Emitido, then "emitida"). In apps/web the commit path publishes each status change (`db/status-changes.ts`) and the shell's `StatusToaster` says it for the relatório whose route is open (only changes this device writes; an edit's toast is passive: no scroll, no pointer events). Amended 2026-10-13 (Matheus, source-deltas): Emitido -generate-> Em revisão, for a queued generate only (a new revision will be built); an `unchanged` answer leaves Emitido. The rule is `advanceOnGenerate(status, outcome)` in `relatorio/status-advance.ts`, asked by `use-generate.ts`. Every op path family is decided once in `FAMILY_DECISIONS` (`status/edited-since.ts`, typed over `PathFamily`): `edit` (`EDITED_SINCE_FAMILIES`, AD-15) or never one with its reason (`NEVER_EDIT_FAMILIES`); a new family in `ops/path.ts` fails `pnpm static` and a kernel test until it is added there.

Code: `packages/domain/src/`: `ops/apply.ts`; `status/table.ts` (statusLabel, isAutoPulled, transitions) and `status/edited-since.ts`; `relatorio/` (`pre-issue.ts`, `integrity.ts`, `progress.ts`, `conclusion.ts`, `parecer.ts`, `instantiate.ts`, `tag.ts`, `suggestions.ts` with compareSuggestion); `checks/calibration.ts`; `parse/` and `format/`; `seed/` (`definitions.ts` getDefinition, `v1.ts`..`v3.ts`, `criteria.ts`, `sections-v1.ts`); `contract/` (`errors.ts`, `sync.ts`, `generate.ts`, `version.ts`). Print functions: see [rendering](/architecture/rendering.md).

*(2026-10-13: `seed/` now also holds `v4.ts`, `v5.ts` and `measurement.ts` (the measurement-table grammar); `relatorio/measurement-evaluation.ts` holds its verdicts and view model.)*
