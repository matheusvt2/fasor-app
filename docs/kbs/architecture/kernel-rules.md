# Kernel rules

What lives once in `packages/domain`, the value shapes, the typed contract and the status table. Seed data is in [seed-versions](/architecture/seed-versions.md). The dated notes below were moved unchanged from `kernel-and-seed.md` on 2026-11-28; a note marked "planning, not built" is kept as history beside the "as built" note that followed it.

The contract number moves with almost every batch; the notes in the seed files name the number each batch took. The current values are `CONTRACT_VERSION` and `MIN_CONTRACT_VERSION` in `packages/domain/src/contract/version.ts` (both 62 on 2026-11-28), and a client below the minimum is answered `426 contract_outdated`.

**AD-2, exists once in `packages/domain`**: `applyOp`, `mergePolicy`, `integrity`, `preIssue` (its rows are also the Sumário row statuses), `progress`, `sheetState`, `syncCounts`, `editedSince`, `instantiateTemplate`, `suggestConclusionPair`, `composeConclusion`, `suggestParecer`, `composeParecer`, `suggestTag`, `suggestNameplateCopy`, `compareSuggestion`, `parse`, `format`, `deadlineFromPriority`, `contextCaption`, `section11Instruments`, `calibrationCheck`, `groupForPrint`, `numberPhotos`, `extractPhotoRefs`, `resolveSection8`, `derivedPoints`, `statusTable`. If a task needs a status, count, text, order or verdict, extend this set. One integration test asserts the Sumário rows (Dexie) and the pre-issue list (Postgres) are identical for the Porto Seguro fixture.

**AD-11 field kinds**: every nameplate, SE and measurement field has `kind` in text, number, date, select, manufacturer, voltage_class. A number is `{raw: "3300", unit, state: measured|not_measured|empty}`, `raw` a decimal string with `.`; dates are ISO `YYYY-MM-DD` or `YYYY-MM`. pt-BR parsing (comma decimal, point thousands, `147G`) lives only in `domain/src/parse`; output formatting only in `domain/src/format`. No floats in storage. Derived cells (VAL CALCULADO) are never typed.

*(2026-10-26, Story 16.4 as built: the AD-11 number value gains a fourth state, `not_applicable` ("N.A" typed in a nameplate or cabine number field), stored `{ raw: '', unit: null, state: 'not_applicable' }`. Its one home is the leaf `parse/pt-br-number.ts` (`NOT_APPLICABLE_TEXT`, `isNotApplicableText`, `NOT_APPLICABLE_NUMBER`, `isNotApplicableNumber`), so `ficha.ts` and `suggestion-group.ts` both import it without the `progress.ts` cycle; every reader of the shape reads `state` before `raw` (print "N.A" with no unit, filled for `isCellFilled` and `cabineProgress`, absent for the ratio, voltage bands and conclusion identity). `contract/ocr.ts` keeps its own three-state number schema, so `schema:ocr` output is unchanged. No seed change. Contract 26, minimum 26.)*

**AD-13 contract**: the client talks to the server only through routes typed in `packages/domain/src/contract` (zod request/response, `CONTRACT_VERSION` header): sync ops and pulls, file PUT/GET, generate, preview, reread, revisions download, auth, health. Error envelope `{code, message, details?}`; routes and families are append-only. *(2026-10-13, Story 14.3: `CONTRACT_VERSION` and `MIN_CONTRACT_VERSION` are 18: the `location/{id}/checklist/...` family, `location_id` on the file and point field families, seed v4. A version-17 bundle's pull answers `426 contract_outdated`.)*

**AD-22 status table**: `packages/domain/src/status` holds `(state, event) -> state`; every transition is a client op on `relatorio/status`, the server never writes it. Table of 2026-10-10 (Matheus, source-deltas): Rascunho -setup_complete-> Em campo; Rascunho -edit-> Em campo for field content only (`countsAsFieldContent` in `status/edited-since.ts`: a sheet value, a sheet concluded or not tested, a cabine's SE and ambiente fields, a photo, a point; structure, a block's config and `relatorio/setup` keep Rascunho); Rascunho or Em campo -generate-> Em revisão; Em revisão -issue-> Emitido, emitted only by "Marcar como enviado ao cliente" (never by a revision's arrival) and offered while nothing was edited since the latest revision; an edit in the `editedSince` family set moves Emitido back to Em revisão. Em revisão means a revision was generated and not yet sent. `relatorio/status-advance.ts` holds the edit emitter (`advanceOnEdit`) and every status sentence (banners, `statusChangeToastText`); `relatorio/sumario.ts` the next-step sentence drawn under the Sumário's status pill (`statusStepText`), `canMarkSent` and the Controle row line ("Rev. N gerada" until Emitido, then "emitida"). In apps/web the commit path publishes each status change (`db/status-changes.ts`) and the shell's `StatusToaster` says it for the relatório whose route is open (only changes this device writes; an edit's toast is passive: no scroll, no pointer events). Amended 2026-10-13 (Matheus, source-deltas): Emitido -generate-> Em revisão, for a queued generate only (a new revision will be built); an `unchanged` answer leaves Emitido. The rule is `advanceOnGenerate(status, outcome)` in `relatorio/status-advance.ts`, asked by `use-generate.ts`. Every op path family is decided once in `FAMILY_DECISIONS` (`status/edited-since.ts`, typed over `PathFamily`): `edit` (`EDITED_SINCE_FAMILIES`, AD-15) or never one with its reason (`NEVER_EDIT_FAMILIES`); a new family in `ops/path.ts` fails `pnpm static` and a kernel test until it is added there. *(2026-10-13, Story 14.3: a site item's result or observation, its photo and a point with `location_id` are field content (`countsAsFieldContent`) and an edit (`FAMILY_DECISIONS['location/checklist']`); on a relatório with a site list the Rascunho step sentence names "as verificações do local".)*

Code: `packages/domain/src/`: `ops/apply.ts`; `status/table.ts` (statusLabel, isAutoPulled, transitions) and `status/edited-since.ts`; `relatorio/` (`pre-issue.ts`, `integrity.ts`, `progress.ts`, `conclusion.ts`, `parecer.ts`, `instantiate.ts`, `tag.ts`, `suggestions.ts` with compareSuggestion); `checks/calibration.ts`; `parse/` and `format/`; `seed/` (`definitions.ts` getDefinition, `v1.ts`..`v3.ts`, `criteria.ts`, `sections-v1.ts`); `contract/` (`errors.ts`, `sync.ts`, `generate.ts`, `version.ts`). Print functions: see [rendering](/architecture/rendering.md).

*(2026-10-13: `seed/` now also holds `v4.ts`, `v5.ts` and `measurement.ts` (the measurement-table grammar); `relatorio/measurement-evaluation.ts` holds its verdicts and view model.)*
