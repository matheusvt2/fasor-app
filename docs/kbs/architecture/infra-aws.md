# Containers and AWS

- Local: docker-compose only (web dev server, api, Postgres 18, MinIO, OCR sidecar under profile `ocr`, `mkcert` and `caddy` for tablet HTTPS). Nothing runs natively.
- Cloud is AWS only: ECS Fargate behind an ALB with images in ECR (api plus in-process worker as one service), RDS for PostgreSQL 18, S3 with versioning, Secrets Manager, CloudWatch Logs, Bedrock for Claude, Textract for cloud OCR. Region `sa-east-1` for data at rest.
- Infrastructure is Terraform in `infra/` (`production/`, `bootstrap/`, `caddy/`, `bin/`), run in containers. Files in `infra/production`: network, compute, ecs, rds, storage, cloudfront, iam, ssm, schedule, budget. CDK was dropped (2026-09-29).
- The app is served at the Elastic IP (Let's Encrypt `shortlived` IP certificate) and, with `app_domain` in the untracked `terraform.tfvars`, at that host name too (regular certificate; A record at the domain's own DNS, not Route 53, created before the apply). Caddyfile: `infra/caddy/Caddyfile`; wiring: `local.primary_url` and `local.trusted_origins` in `infra/production/ecs.tf`.
- Cost ceiling USD 100 per month for everything; `infra/production/budget.tf` alerts before it. Cost every infrastructure choice first.
- One image built once and promoted unchanged; configuration only through environment variables and Secrets Manager. Every external call goes through an adapter (`src/storage`, `OcrProvider`, the LLM client), so switching a service changes `infra/`, not app code.
- Bedrock (Story 11.6): the api task gets `BEDROCK_REGION`, `BEDROCK_MODEL_ID`, `BEDROCK_PROSE_MODEL_ID` and `BEDROCK_ESCALATION_MODEL_ID` from `bedrock_model_id`, `bedrock_prose_model_id` and `bedrock_escalation_model_id` (`infra/production/variables.tf`, `ecs.tf`); `infra/bootstrap/iam.tf` allows `bedrock:InvokeModel` only on Claude Haiku 4.5, Nova Pro, Nova 2 Lite, Qwen3 VL 235B and Mistral Large 3 by exact ARN. The bootstrap apply, the deploy and `llm_provider = "bedrock"` plus `ai_features = "on"` are post-merge steps Matheus runs (`infra/README.md`, "AI features flag").
- Profile `fasor-admin` for the AWS CLI, never stored keys. Deploy story: Story 11.8 (`_bmad-output/implementation-artifacts/spec-11-8-deploy-the-same-images-to-aws.md`).
- Production smoke (2026-10-15, Story 14.10 part 6): `infra/production/smoke.tf` declares a dedicated test company and user (`smoke_company_id`, `smoke_user_email`; password from `random_password` in Secrets Manager, USD 0.40 a month) and the one-shot `smoke-seed` task (`apps/api/src/db/smoke-seed-cli.ts`), which empties that company only and re-seeds it. After health and the tag record, `infra/bin/deploy` runs the reset, `pnpm smoke:production` (`e2e/production/`, tools container, host lock) against the deployed URL, and the reset again as the cleanup, always; a red smoke exits 1 with the failing step and the rollback command, nothing rolls back by itself. `--skip-smoke` opts out. Never part of `verify` or the story gate.
- Epic 18 (planned 2026-10-29, AD-28): a dedicated CloudWatch Logs group `/fasor/production/ux-events` (90 days) receives the devices' usage events through `POST /api/telemetry` (`TELEMETRY_SINK=cloudwatch`; `stdout` everywhere else); one dashboard `fasor-production-ux` and saved Logs Insights queries read the funnel; the app role gains `logs:CreateLogStream`, `logs:DescribeLogStreams`, `logs:PutLogEvents` on that group. Under USD 1 a month. Created by the deploy's Terraform apply after the Epic 18 PRs merge.
- Story 18.3 (2026-10-29): `infra/production/observability.tf` declares the dashboard `fasor-production-ux` (nine Logs Insights widgets) and nine saved query definitions over the literal group `/fasor/production/ux-events`, USD 0.00; the read-only `apps/api/src/db/friction-read-cli.ts` reads sheet spans, re-edits and cells typed after a failed reading from the op log, as a migrate-task override. Runbook `docs/observability.md`.
- 2026-11-03 (batch e18fb, E15-A10 and E18-A2): `infra/bin/deploy` retries the repeatable AWS CLI calls on a lost endpoint (`aws_retry` in `infra/bin/lib.sh`: exit 255 with a connection message, 5 attempts 15 s apart; never `run-task`), prints `infra/bin/deploy --resume --tag <tag>` when it stops after the roll and before the smoke finished, and `--resume` skips build, push, migrate and roll after a read-only check that every service runs the tag. A fourth smoke step `smoke: check the usage events` counts the tag's `session_start` events and the api's `ux_event_sink_failed` lines (outputs `ux_events_log_group`, `api_log_group`), a warning only. *(2026-11-24, Story 30.2 C: a failure of the smoke. 2026-11-25, fix batch e30h: the sink failures are counted from the instant the services were stable and healthy, the new api task's lines only, and a red check names the two logs it read.)* `infra/bin/check` runs `init` and `validate` with `TF_DATA_DIR=.terraform/check`, so an initialised stack passes offline. The smoke's step 6 presses the preview once more when its tab closed before the request (`e2e/production/preview-tab.ts`). `infra/README.md` § Deploy and § Checks.
- Story 30.2 (2026-11-25, batch e30a): the four Bedrock model ids of `infra/production/variables.tf` are validated by their shape (optional `global.` or region prefix, provider, dot, model name; prose and escalation may be empty), applied at the next deploy; the deploy's usage-events check fails the smoke (cleanup still runs, rollback hint printed) and its suite runs tools as `node`; a reading run row's `llm_usage` carries `calls[]` (each billed call's model, prompt version and usage) beside the total.
- E-mail (Epic 26, Story 26.7, 2026-11-21): `infra/production/email.tf` holds the SES domain identity of `email_domain` (untracked tfvars), its configuration set, the app role's `ses:SendEmail` from `no-reply@<email_domain>` only, and two reputation alarms. The DKIM records are typed at the registrar from the `email_dkim_records` output; leaving the sandbox is a one-time CLI request. Runbook: `infra/README.md` "E-mail". The api sends only with `EMAIL_PROVIDER=ses`, set at the deploy of Story 26.6.
- *(2026-11-26, batch e31e, Story 31.8, AD-30)* Voice input's real transcriber is Terraform plus one adapter, applied only on Matheus's word: `infra/production/transcribe.tf` holds the pt-BR custom vocabulary `fasor-production-trade-words` (fed from the tracked `transcribe-vocabulary.txt`, authored from the seed's trade words) and the task-role policy `transcribe-jobs` (`StartTranscriptionJob`/`GetTranscriptionJob` on `transcription-job/fasor-stt-*` and that vocabulary only; the audio is read with the role's existing `s3:GetObject` on the files bucket, no data-access role). `ecs.tf` sets `STT_PROVIDER` from `stt_provider` (default `fake`), `TRANSCRIBE_REGION` (us-east-1, the bucket's and Bedrock's region) and `TRANSCRIBE_VOCABULARY_NAME`. The budget action's deny policy also denies `transcribe:StartTranscriptionJob`. Cost: USD 0.006 a minute batch (confirmed 2026-11-26 from the AWS Price List API, publication 2026-11-21), 600 min a month = USD 3.60, total 92.74 (`infra/README.md` "Cost"). Voice runs in production only with `stt_provider = "transcribe"`, `llm_provider = "bedrock"` and `ai_features = "on"`.
