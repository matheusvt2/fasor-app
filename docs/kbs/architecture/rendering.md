# Rendering

- **One renderer (AD-15)**, server-side, over `RelatorioSnapshot`, a kernel zod schema built by `toSnapshot()` on web and api; a replay test asserts both are byte-equal. `POST /api/relatorios/{id}/generate` carries `{last_op_id, file_ids_expected}`; the server answers `409 not_caught_up` until caught up; the Export dialog flushes sync first.
- The job freezes the snapshot, builds the DOCX with the `docx` library, converts to PDF with LibreOffice headless inside the same job. The TOC is static, in two passes (placeholder numbers, read heading pages from the PDF outline, write them, assert equal, third pass if not). Generate concurrency is 1 per instance.
- Revisions: `revision/{id}` is emitted in the transaction that stores both files, so a failed job consumes no number. `editedSince(snapshot_seq)` gates it: a generate with nothing edited returns the last revision. Preview is the identical job with a RASCUNHO watermark and no revision number; one test asserts preview and issued output differ only by watermark and revision line. The FR-1 brand preview is CSS, not a render.
  *(2026-10-26, Story 16.2: while something was edited since the latest revision, the Export dialog shows the kernel's banner ("Relatório gerado|emitido em dd/mm (revisão N). Alterações desde então geram a revisão N+1 — …", `revisionsBeforeEditsBanner`) and every "Revisões" row ends with " — anterior às alterações". Story 16.3: section 7 lists only numbered photos; a display shot prints after its test tables in section 9 with its caption sentence alone, `PrintPhoto.number` null.)*
- **Print order (AD-16)**: tree order is the engineer's; the renderer never reorders the tree. `groupForPrint(snapshot, scheme)` with scheme `por_local_e_tipo` (default) or `ordem_de_campo`, stored by `relatorio/export/scheme`. The scheme is not exposed in the Export UI at present. *(2026-10-13, Story 14.2 as built: under a cabine `groupForPrint` emits the direct run first (blocks on the cabine itself and the colunas directly under it), then one run per painel in tree order; with `agrupar_por_tipo` on each run is grouped by type. A painel prints as an unnumbered band over its run (upper case, bold white on dark grey `404040`, `painelBand` in `apps/api/src/jobs/generate/sections/section-9.ts`): not a heading, no number, no ÍNDICE line (`tocLines` skips it). A cabine with no painel and the Porto Seguro goldens are unchanged.)* *(2026-10-13, Story 14.4 as built: on a relatório whose seed ships the site list (v4 or later) the first subsection printed for a local carries `localParts`: CARACTERÍSTICAS DA SE, AMBIENTE DE ENSAIO, VERIFICAÇÕES DO LOCAL (ÍTEM · C · NC · NA · OBSERVAÇÕES; a group row shaded `F0F0F0`, bold, across the five columns before each group; labels upper case, numbered 1 to 19; an unanswered item with no mark) and the item photos, before any sheet; the sheets then carry no cabine tables. Every live local prints its numbered heading and these parts even with no equipment, and section 9 prints when no local holds a sheet. With *Agrupar por tipo* on, a type group under a painel is titled with the painel and the local. v1 to v3 print unchanged; the Porto Seguro goldens match unregenerated. Code: `print/group-for-print.ts`, `print/section-9.ts` (`PrintSheetSubsection.localParts`, `PrintRow.group`), `apps/api/src/jobs/generate/sections/section-9.ts` (`GROUP_ROW_FILL`); tests `docx-site-checklist.test.ts`, `e2e/verificacoes-local.spec.ts`.)*
  *(2026-10-13, Story 14.5: with type grouping, `groupForPrint` emits one more kind, `outros` ("Outros equipamentos"), after `transformadores`, holding the sheets of the library types (`isLibraryType`); a run with no library block emits exactly the earlier parts. A library sheet prints a CONFIGURAÇÃO table after its nameplate and one table per enabled measurement test, all computed in `packages/domain/src/print/section-9.ts`; see [measurement-table](/architecture/measurement-table.md).)*
- **Section 8 (AD-26)**: `point.text` is plain text whose only markup is `[[foto:<photo_id>]]`; there is no `photo_ids` field. `resolveSection8` turns tokens into "Imagem NN". Untested entries come from `derivedPoints(snapshot)`, printed after manual points, never stored; a point created from an untested sheet carries `origin: not_tested` and suppresses the derived one.

Code: server `apps/api/src/jobs/generate/` (`job.ts`, `docx.ts`, `toc.ts`, `pdf-outline.ts`, `libreoffice.ts`, `pdf-raster.ts` (certificate PDFs to 150 dpi PNG with poppler `pdftoppm`, 30 s per run, 300 s budget), `certificate-cache.ts` (pages cached at `company/{id}/certificate-pages/v1/{sha256}`), `watermark.ts`, `sections/`, `golden/`), `apps/api/src/http/generate.ts`, `apps/api/src/sync/snapshot.ts`; web `apps/web/src/db/snapshot.ts` and `generate-store.ts`; kernel `packages/domain/src/print/` (`group-for-print.ts`, `section-7.ts`..`section-11.ts`, `layout.ts`, `revisions.ts`, `document-control.ts`), `photos/order.ts` (numberPhotos), `status/edited-since.ts`. Goldens regenerate with `scripts/regen-goldens.ts`. The fixture and goldens may carry the real Porto Seguro data (see [rules](/project/rules.md)).
