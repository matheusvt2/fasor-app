# Usage events

- **Contract (kernel)**: `packages/domain/src/contract/telemetry.ts`. `uxEventSchema` is strict (unknown keys refused) with `v: 1`, `ts`, `session_id`, `device_id` (uuid), `app_version` (`dev` or a commit sha), `name` (`UX_EVENT_NAMES`), `screen` (`SCREENS`, from `screenOf(pathname)`), optional `target` (`TELEMETRY_TARGET_PATTERN`), `kind` (checked per name: `WAIT_KINDS`, `READING_RESULT_KINDS`, `SYNC_RESULT_KINDS`, an `errorCodeSchema` code; no kind on any other name), `outcome` (`UX_OUTCOMES`), `duration_ms` (integer, 0 or more), `relatorio_id` and `block_id` (uuid v7). No free text can pass. `UX_ACTION_TARGETS` and `UX_DIALOG_TARGETS` are the minimum instrumentation; `syncResultKind` maps a finished cycle; `TELEMETRY_ROUTE` (beside `ACCOUNT_ROUTES`), `TELEMETRY_BATCH_MAX = 200`, `telemetry_invalid` in `errors.ts`. Contract stays 28: events never travel in the op stream.
- **Device**: Dexie version 7 adds `ux_events` (`++id, ts`), written only through `apps/web/src/db/ux-events-store.ts` (cap 5 000, oldest dropped). `apps/web/src/telemetry/track.ts` `track()` builds, validates (a failing event is dropped) and queues; it returns nothing, never throws, never logs; before the user's database and device id are known it buffers 50. `SyncProvider` points it at the database (`configureTelemetry`), tracks `sync_result` per finished cycle (offline only on the way into offline), the "Sincronizar agora" / generate / preview waits, dead ops and failed generate, preview and reread as `error`, and readings that landed (`telemetry/readings.ts`, one look per finished cycle), then flushes.
- **Controls**: the `data-telemetry` attribute is a control's one `target` source. `telemetry/instrument.ts` installs, once per load, a capturing `click` listener (`action`, or `retry`/`undo` from `data-telemetry-event`), a capturing `pointerdown` listener (`disabled_tap` on `disabled` or `aria-disabled="true"`), and the `visibilitychange: hidden` beacon; `data-telemetry-screen` on a container (the Export dialog's `export`) names the screen. `TelemetryRoutes` (router root) queues one `screen_view` per pathname, ids only from the route params and only when uuid v7; `useDialogTelemetry` queues the six dialogs' `dialog_open` and `dialog_cancel`.
- **Flush**: `telemetry/flush.ts` after every cycle that ran and on a hidden tab (`sendBeacon`, at most 200 events and 60 000 bytes, offline nothing). Batches of at most 200, oldest first; deleted on 2xx and every 4xx, kept on 5xx and no network; one flush at a time and a row in flight is never sent by another path. The `fetch` itself lives in `apps/web/src/api/telemetry-client.ts` (AR-1).
- **Api**: `apps/api/src/http/telemetry.ts`, behind the session. Not an array, more than 200 items or any item failing the schema: `400 telemetry_invalid`, nothing written. The body's `received_at`, `user_id`, `company_id` are dropped before parsing; the server stamps them. 1 000 events a minute per `user:device` (`FixedWindowLimiter.consume(key, cost)`, always on) answers `429 rate_limited`. The sink (`apps/api/src/telemetry/sink.ts`) is `TELEMETRY_SINK=stdout` (default: one `ux_event` log line per event) or `cloudwatch` (`PutLogEvents` once per batch on `TELEMETRY_LOG_GROUP`, each log event timestamped with the batch's `received_at` while the device `ts` stays in the message, stream `api/<start instant with - for :>/<pid>` created at first use and again after a put finds it gone; `telemetrySinkOf(config)` picks the sink); a sink failure is logged once as `ux_event_sink_failed` with `count` and the route still answers 204. The request log line carries no event content.
- **Infra**: `infra/production/telemetry.tf` (group `/fasor/production/ux-events`, `ux_events_retention_days = 90`, the app role's `logs:CreateLogStream`, `DescribeLogStreams`, `PutLogEvents` on the group and its streams), the two `ecs.tf` environment entries, `VITE_APP_VERSION` passed by `infra/bin/deploy` to `apps/api/Dockerfile.prod`; cost row and runbook line in `infra/README.md`. The deploy's Terraform apply creates the group.
- **Conta**: "Uso do aplicativo", one authored sentence in `copy.account.usageNote` (open for Bruno).
- **Never**: an event in `outbox`, `remote_ops`, `entities` or `applyOp`; a status or count derived from an event; an analytics SDK or cookie.
