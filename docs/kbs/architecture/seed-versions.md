# Seed versions

The seed is versioned code in `packages/domain/src/seed/` (`v1.ts` to `v19.ts`). A relatório keeps the version it was created on; a shipped version is frozen and pinned by a hash in `seed/seed.test.ts`. `SEED_VERSION` is `v19` on 2026-11-28 (`seed/definitions.ts`).

| Versions | Main content | Described in |
| --- | --- | --- |
| v1 to v3 | the eight FO.SERV-03 block types, boilerplate, the standard template | this file (AD-21) |
| v4, v5 | site checklist; the measurement-table grammar and its first library type | this file, [measurement-table](/architecture/measurement-table.md) |
| v6 to v10 | Quadro elétrico, the oil rule, option aliases, `{itens_resultados}`, the √3 ratio factor, the TC list | this file |
| v11, v12 | vector groups, accuracy classes, the row test voltage, Inspeção de QGBT | [seed-v11-v12](/architecture/seed-v11-v12.md) |
| v13 | criteria tables, temperature correction, restrictions, applicability, test help, Malha de aterramento | [criteria-and-judgments](/architecture/criteria-and-judgments.md) |
| v14 | the seed-level `rules` flags, the conclusion and section 10 rules, No-break de comando | [seed-v14](/architecture/seed-v14.md) |
| v15 to v19 | the Epic 25, 27, 28 and 30 rule flags and sheet changes | [seed-v15-v19](/architecture/seed-v15-v19.md) |

Where a note below cites `epics.md` for a story of Epics 1 to 30, the story is now in `epics-archive.md`. **AD-21 seed**: `BlockConfig = {block_type, subtype?, role?, sub_blocks, na_defaults}` is the only thing copied into a Block row, with a `seed_version`. Field definitions, checklists, table grammars, criteria, not-tested reasons and section boilerplate resolve through `getDefinition(seed_version, report_type, block_type)`; `packages/domain/src/seed` (v1, v2, v3...) is append-only so every shipped version still resolves. A criterion needs operator, value, unit, type and source. Source of truth for the seed is the decoded FO.SERV-03, not the UX counts. *(2026-10-08: an amendment is proposed for office-created company equipment types beside the seeded eight — immutable published versions, a resolver context in `getDefinition`, a generic measurement table; settled by `bmad-architecture` before Story 14.6 (renumbered 2026-10-09; Story 14.5 first ships the measurement table and ~~two library types~~ one library type (2026-10-13; the second was dropped on 2026-10-10) as seed v5). Templates reach a new version two ways: the api's `upgradeTemplateSeeds` (`apps/api/src/db/template-seed-upgrade.ts`, run after migrations in `main.ts` and `migrate-cli.ts`) puts `template/{id}/seed_version` on every live template the kernel's `templateSeedUpgrade` says can move, one server batch each, idempotent; and a template saved from an older relatório is born on the current version. No relatório's `seed_version` is ever rewritten.)* *(2026-10-14, Epic 14 QA Q-7: a third way: a client push that writes a template (a create, a duplicate, a restore, any edit) runs the same per-template step in its own transaction (`apps/api/src/sync/template-seed-step.ts`, called from `applyOps` for `origin: 'client'`), so a template a device pushes on an older version after the boot reaches the current one at once; the boot pass stays.)*
