# Suggestions and reading

**Suggestion (AD-12)**: entity `{id, relatorio_id, target_path, value, trust suggested|verify, mode fill|replace, source {photo_id, bbox normalized, ocr_token_ids, reading_run_id}, status pending|confirmed|discarded, prompt_version}`. The reading job emits only `pending` creates. Every sheet cell is `{value, source_suggestion_id|null, op_id}`; any later plain `put` clears the source. "Confirmar" is one batch: `suggestion/{id}/status = confirmed` plus the target value with `meta.source_suggestion_id`. "Confirmar todos" skips `verify`. On applying a suggestion whose target cell is non-empty, the device runs `compareSuggestion`: equal -> auto-confirm batch with `meta.auto = true`; different -> stays pending as `replace`. Pending is the stored status, never inferred; progress, pre-issue, counts and renderer ignore anything not confirmed. A value is `suggested` only if it passes digit coverage over the OCR tokens the model cited, else `verify`; checked on the server. Derived suggestions (conclusion, parecer, deadline) are kernel computations, not rows.

**Reading pipeline (AD-14)**: a photo carries `reading_kind` (plate, display, caption, panel, nc_obs) and `reading_target`, set on the device at capture; `reading_status` is written by `system:reading` ops. File receipt enqueues one pg-boss `reading` job, singleton `(photo_id, reading_kind)`, three attempts then `failed`; `POST /api/photos/{id}/reread` re-enqueues. Two steps behind two interfaces in `domain/src/contract/ocr`: `OcrProvider.read(image)` returns tokens with bboxes, then the LLM structuring step. **The LLM never emits coordinates**; every bbox comes from OCR, the model only cites `ocr_token_ids`. Each run stores a `reading_run` row (provider, model, prompt_version, usage, duration).

Providers by environment: `LLM_PROVIDER` in fake, bedrock (Story 11.6 dropped `anthropic`); `OCR_PROVIDER` in fake, textract, ocr-svc. Both default to `fake`, which replays fixtures from `apps/api/src/jobs/reading/fixtures` so dev, tests and compose need no cloud or key. The backend never uses a personal Claude subscription. Real providers are post-MVP and behind a flag (Story 11.8, AI features off in production until Story 11.6 is merged, deployed and the flag applied in `infra/`).

**Bedrock (Story 11.6, 2026-10-05)**: `providers/bedrock.ts` is one Converse adapter behind both `StructuringProvider` (plate, panel) and `ProseProvider` (caption, NC draft), credentials from the AWS SDK default chain only, one lazily built client per process, `maxAttempts: 1` (pg-boss retries). Structured output is Converse tool use (`record_values` / `record_text`, forced with `toolChoice`), the tool schema derived from the `FieldDef`s, the input validated with `structuringResultSchema` / `proseResultSchema`; OCR tokens go as `t<n>: text` lines, never coordinates. A reply without the tool call or failing the schema, `AccessDeniedException`, `ValidationException` and `ResourceNotFoundException` are permanent; throttling, 5xx and the 60 s timeout are transient. `prompt_version` constants `bedrock-structuring-1` and `bedrock-prose-1`; USD from `BEDROCK_PRICES` (2026-10-05 us-east-1 list prices; a model missing there fails at boot). Settings: `BEDROCK_REGION` (us-east-1), `BEDROCK_MODEL_ID` (Claude Haiku 4.5, `global.anthropic.claude-haiku-4-5-20251001-v1:0`), `BEDROCK_PROSE_MODEL_ID` (defaults to the structuring model), `BEDROCK_ESCALATION_MODEL_ID` (Amazon Nova Pro, `us.amazon.nova-pro-v1:0`; empty disables).

**Escalation (Matheus, 2026-10-05)**: a plate reading whose suggestions are more than half `verify`, or that has none (`shouldEscalate`, kernel `reading/escalate.ts`), is structured once more on the escalation model, and `betterReading` keeps the one with more `suggested` values, then the one with more rows, then the escalation's (the stronger model; Matheus, 2026-10-06, a cascade's usual rule). `shouldEscalate(rows, ocrWords)` is false when the OCR found no word, since a second model has nothing to cite; the run row names the kept model with the usage of both calls summed (`kinds/plate.ts`). A failed escalation call keeps the first reading with its own usage. No escalation provider is built when the escalation model is empty or equals `BEDROCK_MODEL_ID`, nor any Bedrock provider while `AI_FEATURES=off`. Panel, caption and NC draft never escalate. Panel fronts read on their own model, `BEDROCK_PANEL_MODEL_ID` (Qwen3 VL 235B by default; Matheus, 2026-10-06), chosen in the factory by `reading_kind`; plates stay on `BEDROCK_MODEL_ID`. The manual evaluation `apps/api/src/scripts/bedrock-eval.ts` (never run by verify) compares candidates on field accuracy, valid citations, tokens and USD; choosing a cheaper default waits for real nameplate photos.
