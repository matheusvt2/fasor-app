# apps/web/src

- `surfaces/` one folder per screen area: `home`, `login`, `account`, `project`, `relatorio`, `ficha`, `photos`, `points`, `registries`, `templates`, `export`, `sync`; plus `app-shell.tsx`, `contract-outdated-surface.tsx`, `eviction-recovery-surface.tsx`.
- `components/` shared components built from the mock CSS (button, combobox, tri-state-control, suggestion-field, gallery, sync-badge, dialogs, tabs, toast...). Exported through `components/index.ts`.
- `db/` Dexie layer: `schema.ts`, `commit.ts` (write ops), `live.ts`, stores per area, `snapshot.ts`, `drafts.ts`, `file-store.ts`.
- `sync/` engine, client, policy, online. `files/` photo capture, encode, import, geolocation, rescue. `sw/` service worker. `api/` the only typed HTTP calls. `speech/` dictation. `input/` shared touch and pointer layer. `state/` derived state that only renders kernel results. `device/`.
- Roles on screen *(2026-11-21, Story 26.5, AD-29)*: `state/permissions.tsx` holds `PermissionsProvider` (mounted in `app.tsx` `RequireSession`; reads the user's role from IndexedDB with `localRoleOf`, live, so a pull changes the screen with no reload; `loading` until the store answers and, with no role on the device, until a sync cycle completed or the device is offline, then no role holds no key), the one hook `useCan(key)` (true when no provider is mounted, so a surface rendered alone in a unit test reads as Admin), `useCanFn`, `useScreenAccess(path)` and the route guard `RequirePermission`, which wraps every protected route and reads the kernel's `permissionForScreen` (loading waits, refused lands on Home with the kernel's Toast). Rules: a module the role lacks is hidden (Home shortcuts, menu entries, routes); a control of a screen the role uses is disabled with the kernel's `permissionRefusalText` in a `btn-reason` (two side by side share one line); without `relatorio.fill` the ficha, photos, points, section texts and site checks open read-only under one `ReadOnlyBanner` (the ficha's `SheetReadOnlyProvider` takes the cause `role` beside `not_tested`; the role cause draws no per-section line). Web code never names a role. `PermissionsFixture` gives a unit test a known role. After sign-in `LoginRoute` opens the address `RequireSession` kept (`returnAddress` reads only an address of this app).
- The Usuários screen *(2026-11-22, Story 26.9, AD-29)*: route `/usuarios` (behind `users.manage`) and the third Home shortcut; `surfaces/users/` holds `UsersSurface` (the list from IndexedDB, `db/users-store.ts`, overlaid by `GET /api/admin/users` with the kernel's `userDirectory`; after each action the answer's user replaces its row and one `syncNow` is asked; offline or with the route unreachable every action is `aria-disabled` pointing at the Banner line), `UserDialog` (new and edit), and `UsersTabs` (the Tabs row as links, reused by Story 26.10's `/usuarios/papeis`). The network side is `api/admin-users-client.ts` (results, never a throw). Every word and rule is the kernel's `permissions/user-list.ts`.
- Sessions on pause and reactivate *(2026-11-22, e26r)*: a pause keeps the user's sessions, so every 401 while paused is `user_inactive` (`state/session.tsx` keeps the cause `paused` until a sign-in); a reactivation deletes them, so the device lands on Login at its next boot and the sign-in (`doSignIn`) clears the flag and sends the kept outbox. `sync/first-pull.ts` (the sign-in's first company pull) runs only when the company stream was never downloaded; `sync/engine.ts` `pullStream` stores nothing once the engine is stopped. A reactivation refused `role_not_found` says `copy.users.errorRoleNotFound` in a Toast.
- Reactivating a user whose role is gone *(2026-11-22, e26s)*: `surfaces/users/users-surface.tsx` opens `reactivate-dialog.tsx` (`ReactivateRoleDialog`: the user dialog's `RoleOptions`, "Esse papel não existe mais. Escolha outro.") instead of the plain confirmation when `reactivateNeedsRole(entry.role_id, local.roles)` or when the plain `reactivate` answers `role_not_found`; confirming calls `adminUserAction('reactivate', id, { role_id })` (`api/admin-users-client.ts`).
- `copy/pt-br.ts` static surface copy; `copy/ui.ts` component chrome. `styles/` holds `tokens.css`, `components.css` (byte-identical to the mocks) and `app.css` (translations).

Screens are built from the mockups: [mockups-and-css](/ux/mockups-and-css.md). Rules: [ui-system](/architecture/ui-system.md), [ops-and-local-first](/architecture/ops-and-local-first.md).
