## Findings

### Critical

None. No commitment is unusable; three are internally inconsistent and must be corrected before `package.json` and the Dockerfile are written.

### High

**H1 — PostgreSQL 18 cannot run on Fly.io Managed Postgres (row 12, 27).** MPG offers only 16 and 17. Correction to the Stack table: `PostgreSQL | 17 (Fly MPG ceiling; 18 in docker-compose only if a feature needs it — none in the spine does)`. If the team insists on 18, the Fly MPG assumption must change to a self-managed Postgres Machine or another host, and that is a bigger `[ASSUMPTION]` than the version. Keep the local `docker-compose` on the same major as production so migrations are exercised once.

**H2 — TypeScript 7.0 breaks typescript-eslint unless both compilers are installed (row 2).** The spine's "6.0 if a tool lags" reads as a contingency; it is the baseline. Correction: `TypeScript | 7.0 for tsc --noEmit; 6.0 aliased for typescript-eslint` and add to the Consistency Conventions (Testing / lint row) the exact devDependencies: `"@typescript/native": "npm:typescript@^7.0.2"` and `"typescript": "npm:@typescript/typescript6@^6.0.2"`; typecheck script runs `tsc --noEmit` (the 7 binary), eslint resolves `typescript` to 6.0.2. Vite 8, Vitest and drizzle-kit need neither API. Revisit when TS 7.1 ships its API and typescript-eslint follows.

**H3 — Backups cannot rely on R2 object versioning (row 26).** The Environments paragraph says "backups = daily Postgres snapshot plus object-storage versioning"; R2 has no bucket versioning. Correction: replace with "object keys are immutable and never overwritten (UUIDv7 photo ids, revision ids); the storage adapter exposes no delete in the MVP; a scheduled bucket copy (e.g. `rclone sync` to a second bucket/provider) is the object-store backup". This also aligns with AD-20's "purge is a deferred server policy".

### Medium

**M1 — Wrong version numbers on two Stack rows (rows 10, 11).** `@hono/node-server` is 2.1.1, not 4.13; `drizzle-kit` is 0.31.11, not 0.45. Correction: `Hono 4.13 + @hono/node-server 2.1` and `Drizzle ORM 0.45 + drizzle-kit 0.31 (1.0 still rc)`. Harmless now, misleading the moment someone pins from the table.

**M2 — pnpm 10 is two majors behind (row 3).** `latest` is 12.5.1. Correction: `pnpm workspaces | 12`. If 10 is kept deliberately (lockfile stability in a two-week slice), say so; "verified current" is otherwise false for this row.

**M3 — Safari eviction also wipes the app shell, not only the outbox (rows 20, 23).** The 7-day deletion includes Service Worker registrations and the Cache API, and WebKit separately drops unused SW registrations/caches "after a period of a few weeks". After an eviction the tab cannot cold-open offline until it has been loaded online once. Correction to AD-8: state that the warning banner (5-day `[ASSUMPTION]`) protects both the outbox/photo queue and offline availability, and that the mitigation after eviction is "open the app online once"; the PRD Q0 iPadOS check should explicitly include "cold open offline after a Safari restart".

**M4 — `persist()` wording (row 21).** "persist() refused on iOS" should read "`navigator.storage.persist()` exists since Safari 17 but is auto-decided by heuristics (no prompt) that favour Home Screen web apps; in a Safari tab it is effectively denied and does not exempt the origin from the 7-day ITP deletion". The rule ("no reliance on persist()") stands; the reason is now accurate.

**M5 — LibreOffice 26.2 is not in Debian's apt (row 16).** `node:24` images are Debian trixie, which ships 25.2.3. Correction to the Structural Seed Dockerfile comment: `node:24 + LibreOffice 26.2 Still from TDF .deb packages (not apt)`; pin the 26.2.x tarball URL and its SHA in the Dockerfile. Note the 26.2 branch reaches EOL on 2026-11-30, after which Still becomes 26.8: plan one image rebuild.

### Low

**L1 — "library mode" is not a React Router term (row 6).** Use `React Router 8.4 (data mode: createBrowserRouter + RouterProvider, imports from react-router)`. Also record: ESM-only, `react-router-dom` no longer exists, peer React ≥ 19.2.7.

**L2 — Node 24 leaves Active LTS on 2026-10-20 (row 1).** Still supported until 2028; nothing to change for the slice. Optionally note "Node 24 LTS (26 becomes LTS 2026-10-27; move when Fly's base image and pg-boss/sharp engines allow)".

**L3 — Two-pass TOC needs a fixed-height placeholder (row 15, AD-15).** Verified as feasible (headings become PDF outline entries with page destinations; docx's `TableOfContents` would otherwise stay empty under LibreOffice). Not a version issue, but AD-15 should say pass 1 renders a TOC placeholder with the same number of lines as the final TOC, or pagination in pass 2 differs from the outline read in pass 1.

**L4 — Claude image cost lever (row 24).** On Opus 5 / Sonnet 5 images are read at the high-resolution tier (long edge 2576 px, up to 4784 visual tokens); a 2000×1500 display photo costs about 3 900 input tokens. The memlog's per-job estimate (~USD 33 for ~1 100 display shots) is consistent with that. If cost matters, downsampling the upload variant to ≤ 1568 px long edge roughly halves visual tokens; AD-14 may note that the compression numbers deferred in "Photo compression for upload" also set the reading cost.

**L5 — Vision top tier (row 25).** Above 5 M units/month the price is $0.60 per 1 000, not $1.00 as some secondary sources say. Irrelevant at fasor's volume; recorded so the memlog is not "corrected" later from a bad source.

## What was not verified

- iPadOS Safari cold-open offline behaviour on a real device (row 23) — only the platform documentation was checked; the PRD Q0 manual test remains the proof.
- LibreOffice's rendering of `NUMPAGES` in the specific docx output (row 16) — the import path exists in writerfilter and the field maps to the PageCount service, but the "Página X de Y" string is only proven by the renderer snapshot test on the Porto Seguro data set.
- The 26.2 wiki release notes (wiki.documentfoundation.org) and ask.libreoffice.org were blocked by anti-bot pages; the help.libreoffice.org filter-parameter reference was used instead.
