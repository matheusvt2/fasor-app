# Spine Pair Review — fasor

## Overall verdict
Mechanically this pair is clean: every `{path.to.token}` reference in both files resolves (52 unique), all 27 light colors have a `-dark` pair with hex, the 14 contrast ratios claimed in DESIGN.md recompute exactly, 30/30 component names match between DESIGN.md § Components and EXPERIENCE.md § Component Patterns, all seven `sources` resolve, and every inline import link exists. Downstream consumers can source-extract without guesswork on the visual identity, the block model, or the capture-to-document transformation. Two high-impact gaps remain, both in the field-offline promise: the brief's MVP step "nameplate data read by AI from a photo, then confirmed" has no flow, component or state, and the spine never says how a laudo becomes available on a device before the engineer enters a no-signal substation, nor what happens when it is not. Both spines still carry `status: draft`; no key-screen mocks exist, so the two behavior-heavy surfaces (Equipment sheet, Laudo overview) will be built from tables alone.

## 1. Flow coverage — adequate
Sources carry no named UJs or FR IDs (brief + addendum are prose; research is reference). Requirement names were extracted from the brief's "The Solution" (5 steps + offline + web) and "Scope › In (MVP)" (10 bullets), plus the addendum's "Discovery meeting ideas". All six Key Flows have a named protagonist (Bruno / Eduardo), numbered steps, an explicit **Climax** beat and a Failure paragraph (Flow 6 is itself a failure path with a nested failure). Coverage: setup before visit → Flow 1; fill on site (checks, tests, instrument by code, conclusion) → Flow 2; add missing equipment in the field → Flow 3; photos as first-class data → Flows 2, 4; findings become an action plan → Flow 5 step 3; generate DOCX with TOC → Flow 5; works without signal / no photo loss → Flows 2, 6; Project → report hierarchy → Flow 1 step 4.
### Findings
- **high** The brief's MVP flow step 2 includes "nameplate data (read by AI from a photo, then confirmed)" and Scope lists it as in-MVP ("last in the MVP queue"). EXPERIENCE.md mentions it only as a one-line "Deferred" note in § Inspiration & Anti-patterns (line 254): no Key Flow step, no Component Pattern for the confirm-one-by-one review, no state for extraction running / needs connection / failed / low-confidence field, and no DESIGN.md visual for a suggested-vs-confirmed field. In a zero-signal field context (Foundation) the "needs connection" question alone is a design decision a story-dev cannot make (EXPERIENCE.md § Key Flows; § Component Patterns; § State Patterns). *Fix:* add a Component Pattern "Nameplate extraction" (button in the nameplate sub-block; requires connection, says so when offline; returns proposed values rendered as suggestions in `{colors.fora-do-limite-fill}` until each is confirmed; nothing is written until confirmed), a State Patterns row (extracting / offline / failed), a DESIGN.md visual for the suggested field, and one step in Flow 2 (or a Flow 2b) exercising it. If the team wants it out of the UX contract until report generation works, say so explicitly under Open Questions and remove it from the Inspiration "when built" sentence.
- **medium** § Information Architecture "Surface closure" claims every surface has a flow that lands there, but no flow lands on **Registries** or **Account**. The claim cites "Registries + Instrument picker — Flow 2" (Flow 2 only uses the picker) and "Login, Account — Flow 1, Sheet header" (Flow 1 never opens Account). Registries is where the calibration certificate file is uploaded — the input for section 11 of the output — and no flow, Component Pattern or state describes that upload (file types, size, offline behavior) (EXPERIENCE.md § Information Architecture line 54; § Registries; Flows 1–6). *Fix:* add a short office flow (e.g. Flow 0 — "Bruno registers instrument 1T with its RBC certificate") or a Registries step inside Flow 1; specify certificate upload behavior in the Registry row pattern; correct the surface-closure sentence.
- **low** The field path "Checklist row NC › Criar ponto de atenção" (IA row Points of attention; Point of attention card pattern) is never exercised; Flow 5 creates points of attention in the office only. *Fix:* one step in Flow 2 after the NC observation, or drop the NC-row entry from IA if office-only is intended.

## 2. Token completeness — adequate

### Findings
- **medium** The spine's own rule is "load-bearing text ≥ 7:1" (DESIGN.md § Do's and Don'ts row 1; EXPERIENCE.md § Accessibility Floor), but the selected tri-state segment renders the state's ink on its own fill (§ Components › Tri-state control; `components.tri-state-control.*-selected/*-foreground`), and those pairs compute to 5.6:1 (conforme), 5.4:1 (não conforme), 4.9:1 (não se aplica), 5.8:1 (fora-do-limite on its fill, used by the Conclusion control's *Com restrições* and the Measurement field helper). The C/NC/NA letter on the selected segment is the most load-bearing text in the product; a dev following the tokens ships AA-only there under sunlight. Dark-theme equivalents are 6.2–7.8:1. *Fix:* either darken the light fills (`conforme-fill`, `nao-conforme-fill`, `nao-aplica-fill`, `fora-do-limite-fill`) until ink-on-fill ≥ 7:1, or state in § Colors that selected segments draw the letter in `ink-primary` (15.2–15.3:1 on the fills) and use the state ink only for the ring/glyph.
- **low** Breakpoint values (768 / 1280) and the tablet rail width (320px) live only in EXPERIENCE.md § Responsive & Platform; DESIGN.md § Layout & Spacing names phone/tablet/desktop gutters without the breakpoints the spec assigns to that section. ## 4. State coverage — adequate
Walked all 15 IA surfaces against § State Patterns (20 rows) and per-component states. Covered: cold open (session/no session), offline cold open, empty (Home, Templates, Laudo overview, Gallery, Points of attention), draft found, focus, out of limit, required missing, not tested, offline write, photo pending, sync error, sync conflict, storage low, calibration expired, exported-then-edited, permission denied (project), generation failed, session expired offline.
### Findings
- **high** No state or rule covers **laudo availability on the device before going offline**. Offline & Sync specifies writes ("every write lands on the device") and State Patterns covers "Cold open, session, offline → cached laudos render", but nothing says when a laudo (and its registries, templates, photos) is downloaded, whether the engineer can see that it is complete on this device, or what a tap on a non-cached laudo does with no signal. Flow 4 step 1 assumes it ("cached last night on Wi-Fi"). This is the mirror of "never lose a photo": entering a basement with a laudo that is not on the tablet is the product's failure mode, and architecture needs the rule (download all? on open? explicit "Disponível offline" toggle?) to design storage (EXPERIENCE.md § Offline & Sync; § State Patterns; § Sync status surface). *Fix:* add an Offline & Sync bullet stating the download rule and an "available on this device" indicator (e.g. a Sync badge state or a line on the Laudo card "No aparelho · atualizado 21:40"), a State Patterns row "Laudo not on device, offline" with its treatment, and a Sync status section listing downloads as well as uploads.
- **medium** **Camera / file permission denied** by the browser is not a state; the "Permission denied" row covers project sharing only. The Photo capture sheet depends on `getUserMedia`; iPadOS Safari and Android Chrome both surface a denial that leaves "Tirar foto" dead (EXPERIENCE.md § State Patterns line 203; § Component Patterns › Photo capture sheet). *Fix:* add a row: denied → inline message in the capture sheet with "Escolher da galeria" as the fallback and the OS path to re-enable; never silently no-op.
- **medium** No **in-progress** states: export generation on the server for a 119-page DOCX/PDF (Export dialog goes from choice to "download"), initial data load of a 94-sheet laudo, and the photo upload run in Sync status (Flow 6 step 3 "uploads 31 photos") have no visible progress treatment (§ State Patterns; § Component Patterns › Export dialog). *Fix:* one row "Working" (export generating / photos uploading / laudo loading) with copy ("Gerando DOCX…", "12 de 31 fotos enviadas"), what stays interactive, and cancel rules.
- **low** "Cold open, no session, offline" (a second executor's first login inside the substation) is undefined; Login form says session persists but not what the form does with no network. Project with no laudos and an empty Instruments registry (Instrument picker with nothing to pick) have no empty state. *Fix:* three short rows.
