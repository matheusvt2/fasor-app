## Defects, by severity

No P1 or P2 defects. Every Epic 20 check that could be run held.

- **D1 (P3, pass tooling, not the product):** `.scratch-prodpass/prodpass.sh login` now gets 403 `forbidden_origin`. Its Python sign-in posts JSON with no `Origin` header, and Story 20.13's guard refuses a mutating `/api` request that has no Origin and no `Sec-Fetch-Site: same-origin`.
  - Reproduce: `prodpass.sh login` prints "sign-in HTTP 403".
  - Fix (one line in the git-excluded helper): add `'origin': url` to the request headers. This pass used a scratchpad copy with that header, and sign-in returned 200.
- **D2 (P3, header residue):** the plain-HTTP redirect still sends `Server: Caddy`, and every HTTPS response carries `Via: 1.1 Caddy`. The domain block itself meets Story 20.13 (HSTS present, `Server` dropped), but these two headers still reveal the proxy.
  - Reproduce: `curl -sSI http://app.fasorengenharia.com.br/` shows `HTTP/1.1 308` with `Server: Caddy`. `curl -sSI https://app.fasorengenharia.com.br/` shows `via: 1.1 Caddy`.
  - Possible change: `-Via` in the domain block's `header` directive, and an explicit `http://` site block with `-Server`.

- A cookie injected onto an empty device opens "Dados deste aparelho foram apagados". This is AD-8's eviction screen by design (`state/session.tsx`, "session cookie present, database absent"). A form sign-in never shows it. I used it on purpose for check 8.
