## Intent

**Problem:** Batch A (Stories 4.1/4.3, PR #25) left two tracked stubs and no status wiring: `/relatorio/:id/setup` shows a placeholder sentence per étapa instead of the real bands (Story 4.2), `/relatorio/:id/secao/:blockId` shows the resolved section text read-only instead of the editor (Story 4.7), and nothing ever writes `relatorio/status` or warns that an edit after issue creates a new revision (Story 4.6). Until these land, a relatório can never leave Rascunho, its cover/responsável/instruments/altitude data can never be entered, and a section's per-job wording can never be adjusted.

**Approach:** In the kernel, extend `relatorioSetupSchema` with the fields the setup bands write (`escopo`, `exclusions`, `additional_info`, `art_trt_number`, `instrument_ids`, `site_altitude_m`, `site_altitude_confirmed`, `next_intervention_date`, `next_intervention_justification`); add `isSetupComplete`/`setupIncompleteReason` (AR-21), `sectionVariables`/`section3Text` (the one place `{obra}`/`{escopo}`/exclusions resolve, read by this batch's Section text surface today and by batch D's renderer once merged), and the AD-22 emitter `advanceOnEdit` wired into `commitBatch` so any relatório-scoped batch on an Emitido relatório appends `relatorio/status = em_revisão` once. In `apps/web`, replace `setup-stub-surface.tsx` with the five Etapa bands plus the "Conclusão e parecer" placeholder band (Story 4.2), replace `section-text-surface.tsx` with the plain-text editor with variable chips reusing Story 3.6's DOM helpers (Story 4.7), and add the Em revisão/Emitido banner and the header Overflow's backward-move Confirm dialog to the Sumário (Story 4.6).

## Boundaries & Constraints

**Always:** the kernel computes every status, count, completeness reason and resolved text once (`packages/domain`); `apps/web` renders from Dexie and writes only through `commitBatch`/`commitFilePick`/`undoBatch`; every autosave follows the existing `useFieldCommit` idle/blur/close pattern (`50-relatorio-setup.html`'s "Salvo automaticamente" note); disabled buttons use `aria-disabled` + `disabledReason`, never `isDisabled`; every screen uses the mock's class names and pt-BR copy verbatim where the mock draws the same field this story's AC asks for (mock rules and copy this story does NOT use — the mock's own Etapa numbering, "Cidade", "Empresa executora" as an editable field, and the full "Conclusão e parecer"/parecer-generation UI — are out of this story's slice per `epic-4-context.md` and the epics.md AC, and are left for the AC's own band structure instead, see Design Notes); every `.frame-*` mock rule first rendered here gets its `app.css` translation with a comment naming the mock rule; every destructive/undo action moves focus deliberately (E3-A8); no emoji, no `laudo`, no client material outside the Porto Seguro fixture; new copy goes in exactly one home (derived text in the kernel, static surface copy in `pt-br.ts`, component chrome in `ui.ts`); `packages/domain/src/schemas/snapshot.ts` (`RelatorioSnapshot`) is NOT edited by this batch (batch D/4.8 owns it, runs in parallel) — status and revision data this batch needs are read straight off `EntityState` the same way `sumario-surface.tsx` already reads `equipment` (`[...state.entries()].filter(...)`), never through the snapshot.

**Never:** do not build the location tree body, the block palette, or cabine SE/env editing (4.4/4.5, batch B, in `Section9Tree`/tree Overflow); do not build the "Conclusão e parecer" band's parecer verdict/generated-summary content (Epic 7); do not build the Export dialog or the generate job (4.8, batch D); do not add a rich text editor (plain text + chips only, FR-12 deferred); do not add drag-and-drop reordering to the exclusions list (a plain list of fields, per epics.md); do not touch `tokens.css`/`components.css` (byte-identical by test); do not edit `packages/domain/src/schemas/snapshot.ts` or `apps/api` rendering code (batch D territory — this batch only adds kernel functions batch D can call once merged); do not build a picker for multiple backward-status targets (one Confirm dialog offering the immediate previous status only, per Design Notes); do not touch `Section9Tree`'s tree body (`section-9.tsx`, batch B's stub to fill) beyond, if at all, reading revision rows for the banner — the banner lives in the Sumário header, not section 9.

## I/O & Edge-Case Matrix

| Scenario | Input / State | Expected Output / Behavior | Error Handling |
|----------|--------------|---------------------------|----------------|
| Setup completeness | client present, dates present, `responsible_user_id` set to a user with `registration_number`, `setup.art_trt_number` set, `setup.instrument_ids` has 1+ id | `isSetupComplete(snapshot)` true; `setupIncompleteReason` null | No error expected |
| Setup completeness, one gap | any one of the above missing (e.g. `art_trt_number: null`) | `isSetupComplete` false; `setupIncompleteReason` names the first missing item in a fixed order (client, service_start, service_end, responsible_user_id, registration number, ART/TRT number, instruments) as "Concluir dados do relatório: falta ⟨o quê⟩" | No error expected |
| Concluir dados do relatório | setup complete, status `rascunho` | `statusTable('rascunho','setup_complete')` = `'em_campo'`; one `relatorio/status` put is committed; the button becomes unavailable again only because the status is no longer `rascunho` (idempotent: pressing it again on `em_campo` is a no-op, the button reads its own status-gated copy) | No error expected |
| Altitude prefill | Geolocation grants a position, `setup.site_altitude_m` null | field shows the rounded meters (or "< 1000 m" per FR-16's own wording) as a Suggestion field with "Confirmar"; declined/unavailable geolocation leaves the field empty, typed by hand | Geolocation error/denied: field stays empty and typeable, no error surfaced (State Patterns has no "GPS failed" state for this field) |
| Altitude confirm | user presses "Confirmar" | `relatorio/setup` puts `site_altitude_m` (already showing) and `site_altitude_confirmed: true` in one batch; asked once per relatório (guarded by `site_altitude_confirmed`), never re-asked on a sheet | No error expected |
| Instrument uncheck while referenced | instrument checked, `isInstrumentReferenced(id, blocks)` true, user unchecks | the row stays checked in `setup.instrument_ids`'s op (the write is refused client-side) and an inline note under the row says it stays in section 11 because a sheet uses it | No error expected (refusal, not a throw) |
| `advanceOnEdit` | relatório `status: 'emitido'`, a batch containing a `block/{id}/order_key` put (an `editedSince`-family op) and no `relatorio/status` op of its own | `commitBatch` appends one more `relatorio/status` put with value `'em_revisao'` (via `statusTable('emitido','edit')`) to the same `batch_id` | No error expected |
| `advanceOnEdit`, not emitido | relatório `status: 'rascunho'` or `'em_campo'` or `'em_revisao'`, any batch | no extra op appended (`statusTable(status,'edit')` is null for every status but `emitido`) | No error expected |
| `advanceOnEdit`, non-edit op | relatório `status: 'emitido'`, a batch containing only a `suggestion/status` or `relatorio/export/scheme` put (outside `EDITED_SINCE_FAMILIES`) | no extra op appended | No error expected |
| `advanceOnEdit`, op already sets status | relatório `status: 'emitido'`, a batch that itself contains a `relatorio/status` put (a manual backward move) | no extra op appended (the batch already carries the transition the caller intended) | No error expected |
| Banner text | latest `revision` row `{number: 2, created_at: '2026-09-10T12:00:00Z'}`, status `emitido` | `issuedBannerText(revision)` = "Relatório emitido em 10/09/2026 (revisão 2). Alterações geram a revisão 3." | No error expected |
| Banner, em_revisao without a prior issue | status `em_revisao`, no `revision` row exists | banner text is null (not rendered); this is the ordinary "Em campo → Em revisão" first pass, never issued yet | No error expected |
| Backward move | status `em_revisao`, header Overflow "Voltar para Em campo" confirmed | one `relatorio/status` put with value `'em_campo'` (`manualMove('em_revisao','em_campo')`); the server never writes it | No error expected |
| Backward move, already at Rascunho | status `rascunho` | the header Overflow carries no backward-move item (nothing to move back to) | No error expected |
| Section text default | `block.config.section_text: null`, section type `section_2` | the area renders `defaultSectionText(seed_version, 'section_2', today)`; "Restaurar texto do template" is `aria-disabled` (nothing to restore) | No error expected |
| Section text edit | user types, chip-inserts `{cliente}`, tabs away | one debounced `block/{id}/config` put (whole `BlockConfig` with `section_text` set to the serialized text), the template's own text untouched (FR-13) | No error expected |
| Section text restore | `section_text` non-null, "Restaurar texto do template" pressed | `block/{id}/config` put with `section_text: null`, area re-renders the seed default, toast "Texto do template restaurado nesta seção" with "Desfazer" | No error expected |
| Section 1/3 variables | `setup.local: 'das Torres A e B da Porto Seguro'`, `setup.escopo: '...'`, `setup.exclusions: null` | `sectionVariables(snapshot, responsibleName).obra` = the `setup.local` text (falls back to `project.site` then `project.name` when `setup.local` is null); `section3Text(seed_version, today, null)` = the seed's own 3 exclusion items flattened after the fixed paragraph | No error expected |
| Section 3 exclusions overridden | `setup.exclusions: ['Item A', 'Item B']` | `section3Text(seed_version, today, ['Item A','Item B'])` keeps the seed's fixed paragraphs and "Exclusões:" line, replaces the three seeded items with the two given ones | No error expected |
