## Coordinator decisions, gap by gap

- **G6 (P1), display reading dead in production.** Option 1 of the pass report: the display route runs the `PP-OCRv5_mobile_det` text detector. Reasons: the server detector asks 5.6 GB on CPU for a 1200 x 900 photo and no instance under the USD 100 ceiling holds it; Bedrock vision for displays would drop the token boxes the kernel's display parser and the crops read; a lower `OCR_DET_LIMIT_SIDE_LEN` on the server model is unproven. Rules: the plate route (`/read`) keeps the server detector only if the mobile one fails the plate accuracy tests (`services/ocr/tests/test_fixture_plate.py`, `test_api.py`), and then that detector loads lazily on the first `/read` (production never calls it: plates and panels go to Textract since 2026-10-05), so the production process holds the mobile detector and the recognizer only; if the mobile detector passes the plate tests too, one detector serves both routes and the server model leaves the image. The six display fixtures must read green under a 1536 MiB cgroup limit (the ECS `memoryReservation`); the measured `memory.peak` goes in the PR body and in `infra/README.md` § "Memory on the 4 GiB instance". `docker-compose.yml` `ocr` gains `platform: linux/amd64` (paddlepaddle publishes no aarch64 wheel, `infra/README.md`; the deploy already builds `--platform linux/amd64`; on this arm64 host the service runs under emulation). No Terraform change, no api change, no kernel contract change. Fallback if the mobile detector fails a display fixture: the server detector with `enable_mkldnn=True` and a lower `limit_side_len` on the display route, measured under the same cap; the PR says which landed.
- **G8 (P2), long NC phrase chip overflows at 390 px.** The chips of "Observações sugeridas do item N" (`copy.ficha.chipsLabel`, Story 9.5) wrap their text inside the pill instead of widening the sheet: an authored rule in `app.css` scoped to that chip row (`max-width: 100%; white-space: normal; text-align: left; min-width: 0`), `components.css` untouched, the other `.chip` rows (status, "Hoje", recent) keep the mock's `nowrap`. DESIGN.md wins if it states how long chip text behaves. Checked at 390 px by an e2e: `scrollWidth <= clientWidth` with a 66-character learned phrase on the sheet.
- **G1 (P3), console error on an empty device's first load.** `apps/web/src/sync/engine.ts` `queuePulledPairs` logs `merge pairs of a pull failed` on the recovery screen of a device with no rows. Reproduce in a unit test of the engine (a pull into an empty database while the recovery screen holds), fix the cause (not the log line), and assert no console error in the device-wiped recovery e2e.
- **G2 (P3), the sections palette adds a duplicate section.** The template composer's "Seções" palette offers only the FO.SERV-03 sections the template does not hold; a section already present is not offered (hidden), unless the composer mock shows a disabled state for it, then disabled with that look. Unit test on the palette; a clause in the composer e2e.
- **G3 (P3), import toast claims a caption that was not applied.** `packages/domain/src/photos/gallery.ts` `importDoneToast` takes the caption state: with a caption, today's "N fotos adicionadas — legenda aplicada" byte-identical; with none (Geral, empty field), "1 foto adicionada — sem legenda" / "N fotos adicionadas — sem legenda" (authored, open for Bruno, vocabulary of "ficou como Geral, sem legenda"). The caller passes the state; `apps/web` composes nothing.
- **G4 (P3), cabine "Tensão secundária" refuses `380/220`.** The field accepts the two-level form the FO.SERV-03 practice writes: digits, a slash, digits (`380/220`, with the pt-BR decimal allowed on each side), stored as typed in `raw` with unit `V`, printed "380/220 V" by `cabineLineText` and section 9 as the Porto Seguro fixture already stores it (`fixtures/porto-seguro/small/op-log.ts` `secondary_kv: measured('380/220', 'V')`).
