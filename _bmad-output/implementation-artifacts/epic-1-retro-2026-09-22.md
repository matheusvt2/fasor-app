## Findings

Each finding lists its source. **Reverified** means the parent re-opened the primary source after the reviewers reported it, as the rubric requires.

### Aggregate view: size growth

- **Clean.** The largest source file is `packages/domain/src/schemas/entities.ts` at 499 lines, and it is declarative zod. The most-churned logic files are `packages/domain/src/ops/path.ts` (404), `apps/web/src/sync/engine.ts` (325), `account-surface.tsx` (267) and `state/session.tsx` (249). No god-class formed. Disposition: accept.

### Aggregate view: architecture delta

- **Clean at the boundary level.** Lint enforces import direction, where `fetch` may appear and where Dexie may appear (`eslint.config.js:44-113`, `scripts/tooling.test.ts:17-59`). Three reviewers found no hard AD-1..AD-24 violation.
- **AD-10 typing gap.** `applyOps(db, companyId: string, …)` (`apps/api/src/sync/apply.ts:174`) and `toSnapshot` (`sync/snapshot.ts:15`) bypass the branded `CompanyId`. Source: fable, opus. Disposition: fix (A7).

### Aggregate view: duplication map

- **F-DUP-1: two confirm dialogs, two radiogroups.** `components/confirm-dialog.tsx` (1.2) duplicates `surfaces/account/sign-out-dialog.tsx` together with `use-aria-modal.ts` (1.3). `components/segmented-control.tsx` (APG, fixed in PR #7) duplicates the click-only group in `registration-dialog.tsx:103-118`. Reverified: `role="radiogroup"` at `:103`, and no `onKeyDown` or roving `tabIndex` in the file. QA D-10 saw two Tab stops. Root cause: 1.3 ran in parallel with 1.2, and the port promised in PR #5 ("fica para a Story 1.6") was done only for Account's "Sair" and "Editar". Disposition: fix (A5). Lesson: parallel stories must list which shared pieces they stub, and the stub removal becomes a tracked item.
- **F-DUP-2: status words defined twice.** `packages/domain/src/status/table.ts:16-21` against `apps/web/src/copy/ui.ts:26-31`, plus a shadow `RelatorioStatus` type in `components/status-pill.tsx:3`. Disposition: fix (A7).
- **F-DUP-3: two reset mechanisms.** `scripts/test-reset.ts:11` (guessed table list) against `resetTestCompanyData` in `apps/api/src/db/seed.ts:172`. Disposition: fix (A6).
- **F-DUP-4: two 401 paths.** In session, the pointer is kept (`engine.ts:263-265`). At boot, it is cleared (`state/session.tsx:281-290`), which strands offline work behind Login. Source: opus. Disposition: fix (A8).

### Aggregate view: pattern divergence

- **F-PAT-1: pre-1.2 surfaces hand-roll markup.** Login (`login-surface.tsx:102-127`), `RelatorioCard` (`relatorio-card.tsx:31-60`) and `banner-slot.tsx:151-160` do this, and 7 of the 13 shared components have no production caller. Source: fable, opus, sonnet. Disposition: fix (A5).
- **F-PAT-2: mock container classes used as breakpoints.** `components.css:667` switches the status board to 2 columns only under `.frame-phone`, a mockup frame class that the app never applies. Reverified. The same pattern produced **U1** (phone overflow). `components.css:17` scopes the font to `.frame, .frame *`, which produced **U2** (dialogs in Times New Roman, because the React Aria portal renders outside it). This is a design-system translation gap, not a story bug: the mock CSS encodes viewport and scope as container classes, and the app must map them to media queries and a root scope. Disposition: fix (A5). Lesson: a written rule for translating `.frame-*` selectors, plus a phone-width and portal check in the browser pass.

### Aggregate view: spec-to-implementation reconciliation

- **F-SPEC-1 (unmet AC): PRD Q0 manual proof on iPad and Android never ran.** Stories 1.7 AC 3 and 1.8 AC 5 require it; `_bmad-output/test-artifacts/manual/offline-proof-script.md:3` reads PENDING and no dated result exists. Source: all four. Disposition: fix (A1, Matheus).
- **F-SPEC-2 (unmet AC): a new shell activates with ops pending.** Story 1.8 AC: "a new shell activates only on the next launch when the outbox is empty". `holdShell` is a module variable in the worker (`apps/web/public/sw.js:37`, set at `:119`), so it is lost whenever the browser stops an idle worker. Reverified. QA reproduced the failure end to end (D-1: `index-CgqpUOlB.js` served after reopening, with "1 pendente"). The PR #8 review patch fixed the in-session case and missed the lifecycle. Disposition: fix (A3).
- **F-SPEC-3: identity and kernel disagree on id shape.** Identity user ids are slugs (`apps/api/src/db/seed.ts:69`, `idFor('user', email)`), but the kernel expects uuidv7 (`packages/domain/src/schemas/entities.ts:141-147,184`, `ops/path.ts:123`). The seed CLI example company id is v4 (`scripts/seed-users.ts:21`), `asCompanyId` accepts any uuid (`company-id.ts:19`), and `opShape.company_id` is `uuidV7Schema` (`op.ts:31`). All reverified. Visible effects: Sync status lists `seed-user-a-teste-local`, the eviction screen says "0 pessoas da equipe" (QA D-6), and a company provisioned as documented can never sync. Source: opus, fable, sonnet, QA. Disposition: fix (A2, architecture decision).
- **F-SPEC-4: the registration save bypasses the op log.** `saveRegistration` does `fetch('/api/account/registration')` (`apps/web/src/api/auth-client.ts:139-144`), which is not one of AD-1's five named actions. Editing offline is therefore impossible (`registration-dialog.tsx:64`). Reverified. Source: sonnet, fable, opus. Disposition: fix (A2).
- **F-SPEC-5: `device_id` is still caller-chosen in `commitBatch`.** Spec 1.5 `deferred[2]`; the fixture falls back to the user id (`field-fixture-surface.tsx:58`). Disposition: fix before the first Epic 2 op emitter (A4).
- **F-SPEC-6: Toggle, Checkbox and grouped FilterChip have no visible on state.** Spec 1.2 `deferred[0]`, spec 1.6 `deferred[2]`; the fix pattern is proven on `SegmentedControl`. Disposition: fix (A5).
- **F-SPEC-7: Story 1.7's CI AC was never struck through** to match the no-CI decision (`epics.md:720-722`). Source: sonnet. Disposition: spec reconciliation (A9).
- **Accepted deviations**, recorded so later retros stop re-flagging them:
  - `syncCounts(outbox)` instead of `(snapshot, outbox)`: no snapshot exists before Epic 5.
  - "Baixando…" without "n de m": needs `progress`.
  - Shortcut cards, "Continuar" and "Ver sumário" are `aria-disabled` with a reason: their destinations belong to later epics.
  - Coalescing option (b) (re-materialize on pull) is the decision; option (a) is closed.

### Process findings

- **P1: the independent review caught what the internal review missed.** In PRs #4-#8, every story with UI or security weight had a medium or high issue the 4-layer review missed or patched wrongly: Combobox `aria-disabled` (#4), 5xx shown as "Senha incorreta" and Host-header trust (#5), cross-tenant dedupe (#6), the Tema keyboard commit (#7), the SW hold and the dead-end eviction screen (#8). In two cases the internal patch introduced the defect (1.3's 5xx boundary, 1.6's keyup commit). Source: PR comments. Lesson: the independent review must re-examine the patch itself (A11).
- **P2: F-SPEC-2 shows the independent review is not the last line either.** Its own patch fixed the in-session case and left the lifecycle gap, which only the real-browser QA exposed. Library and platform semantics (React Aria DOM shapes and portals, the SW lifecycle, event ordering) were assumed rather than probed. Lesson: a mandatory hands-on browser pass for UI and SW stories (A11; memory `human-style-e2e-testing`).
- **P3: model and effort fit.**
  - fable/high on 1.4 and 1.5, and opus/high on 1.8, fit.
  - Two reviewers judge four assignments too low:
    - sonnet/high on 1.2: React Aria DOM shapes;
    - opus/medium on 1.3 and 1.6: security and keyboard a11y;
    - sonnet/medium on 1.7: a static server with a traversal guard, untested in its first pass.
  - Lesson: opus/high as the floor for component-library, a11y-keyboard and security-adjacent stories (A11).
- **P4: 7 of 8 specs carry `oversized`,** and several ACs depend on artifacts from later epics (`progress`, the Porto Seguro fixture, sheet surfaces), which forced deferrals by construction. Lesson: recalibrate story size, and write ACs only against what exists (A11).
- **P5: the epic was marked `done` in `sprint-status.yaml` (`00de851`) with its own device-proof AC pending,** and PR #1 had no independent review. Lesson: the epic-close gate checks every AC, manual ones included (A11).
- **P6: parallel worktrees had a cost.** Merges needed conflict resolution (spec 1.3 "Merge with main"), rebase and force-push had to be replaced by merge commits, and one worktree was given host ports above 65535 by the orchestrator. Recorded in memory `story-delivery-pipeline`. Lesson: a checklist for starting a parallel story (ports, stubs, merge plan).
