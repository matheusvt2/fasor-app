## Constraints (win over the stories where narrower)

- Scope: `packages/domain` and `apps/api` only, plus `docker-compose.yml` (`STT_PROVIDER`), `docs/kbs/*`, `epics.md` outcome lines. No file under `apps/web` except the minimal typed change that `pnpm static` forces (an exhaustive switch over the `file` union or the Suggestion source). No UI. Do not touch the web speech engine.
- No seed change, no print change; every golden stays byte-equal (a red golden: stop and report).
- Names are AD-30's: file kind `audio`; `audio_target`, `audio_status` (`queued`,`transcribing`,`done`,`failed`,`dismissed`), `quality`, `transcript_heard`, `transcript_written`, `transcription_run_id`; `meta.source_audio_id`, `meta.ai_written` (meta key only declared here if the op meta schema is closed; the write route is NOT built here); Suggestion `source: {audio_id}`; actor `system:transcription`; job `transcription`; `STT_PROVIDER` (`fake`|`transcribe`); `SpeechProvider`, `WritingProvider`; kernel folder `packages/domain/src/audio/` exporting `pendingAudios`, `failedAudios`, `audioQualityVerdict`, `writtenTextGuard`, `audioWritingLevel` (the writing level of a target). Route `POST /api/audios/{id}/retranscribe`. `POST /api/relatorios/{id}/write` is Story 31.9: NOT built.
- Contract: 62 (`CONTRACT_VERSION` and `MIN_CONTRACT_VERSION` both, following the 61 / 60 precedent: a bundle at 61 cannot parse an `audio` file row or an audio-sourced Suggestion, so its pull answers `426 contract_outdated`, pushes still accepted). Append the paragraph to `contract/version.ts` and update the contract tests that assert the number (grep `61` in contract tests and `apps/api/src`). An op from a bundle at 61 must still fold and be accepted.
- `STT_PROVIDER` (`fake` default, `transcribe` accepted) in `apps/api/src/config.ts` with its test, and in `docker-compose.yml`. Selecting `transcribe` at boot fails with a clear message that the adapter arrives with Story 31.8 (its adapter is NOT built).
- Writing step: new `WritingProvider` interface (`write({text, level, context}) -> {text, usage...}`) with a `fake` (replays fixtures under `apps/api/src/jobs/transcription/fixtures`) and a `bedrock` adapter on `apps/api/src/ai/bedrock.ts` selected by `LLM_PROVIDER`. Prompts versioned like the reading prompts and living beside them (follow `apps/api/src/jobs/reading/` structure and its prompt-version convention). `ProseProvider` is not reused.
- Red first for each new kernel rule: write the test, run it red, then implement; say so in the report (list the kernel tests that were seen red).
- Strings authored (status words, count sentences) are in `packages/domain`, marked `// authored (Story 31.x, listed for Bruno)`; list them in the report.
- No emoji. English code and comments. Never read `docs/context/`.

## Code map (verify by grep; the shapes below are the intent)

Kernel (`packages/domain/src`):
- `schemas/entities.ts`: add `audioFileRowSchema` (kind `audio`, `fileBase` fields, `audio_target` closed zod union: checklist item observation `{type:'item', block_id, item_id}`, sheet field `{type:'sheet_field', block_id, field}`, photo caption `{type:'photo_caption', file_id}`, point `{type:'point', ...}`, section/setup field `{type:'section', ...}`/`{type:'setup', ...}`, measurement table `{type:'table', block_id, table...}`; take the real address shapes from how cells/ops address those fields today), `audio_status`, `quality` (level, clipped_share, noise_ratio, duration_ms, speech_ms, verdict `good|poor`, plus `reasons`), nullable `transcript_heard`, `transcript_written`, `transcription_run_id`). Other file kinds must refuse these fields (strict). Join `fileRowSchema` union; check `FileRow` readers, `otherFileKindSchema`, op validation (`ops/`), scope table (`audio` is relatorio scope like photos), `merge`, fold, and `ENTITY_FIELDS`-style key lists.
- Suggestion source (`reading/` or `schemas`): a union member `{audio_id}` with no bbox and no tokens; existing suggestions still parse (add a test with an old row).
- `audio/` folder: `status.ts` (status words, `pendingAudios(files)`, `failedAudios(files)`, count sentences with plural by the kernel, e.g. "1 áudio aguardando transcrição" / "2 áudios aguardando transcrição", failed sentence), `quality.ts` (thresholds in ONE exported const, `audioQualityVerdict(measures)` -> `{verdict:'good'}|{verdict:'poor', reasons:[...]}` with reasons `low_level|clipping|noisy|too_short|no_speech`), `writing-level.ts` (`audioWritingLevel(target)` -> `polish|report|reading` by the epic's table: polish = photo caption, NC item observation, measurement-test reason, "Não ensaiado" reason and note, point text, setup texts; report = ficha Observações, Texto da conclusão, parecer summary, section texts; reading = measurement table), `guard.ts` (`writtenTextGuard(heard, context, written)` -> `{ok:true}|{ok:false, reasons}`: numbers (pt-BR decimals, thousands), units, TAGs not in heard or context; or a number/unit/TAG of heard missing in written; reuse `parse/pt-br-number.ts`), `context.ts` (the kernel assembles the prompt context from the snapshot: field, equipment type and TAG; checklist item and answer; ficha conclusion: picked result, NC items, readings outside criterion; parecer: counts and restrictions; keep it as pure functions over the snapshot types the server holds), `index.ts`; export from the package index.
- Prose write helper: a pure `audioWriteOps`/`appendAudioText(current, text)` rule: append after the value already there (new paragraph for rich text), except a photo caption still equal to the computed context caption which is replaced; `meta.source_audio_id` set. Kernel-owned so the server only applies it.
- `contract/version.ts` (62). Provider interfaces `SpeechProvider`/`WritingProvider` types in `packages/domain/src/contract/` (AD-30 "Binds") if that is where `reading.ts` puts its provider types, else beside the job.
- Reuse `parse/utterance.ts` (`parseTableUtterance`) for the reading branch.

Api (`apps/api/src`):
- `config.ts`: `STT_PROVIDER`. `jobs/transcription/`: `worker.ts`, `job.ts` (the job body, pure steps testable), `providers/speech-fake.ts`, `providers/writing-fake.ts`, `providers/writing-bedrock.ts`, `prompts` (versioned), `fixtures/`, a `transcription_run` table (Drizzle schema + forward-only migration: provider(s), model, prompt version, audio seconds, tokens, USD, duration, guard outcome / fallback reason, `not_a_reading`) and its repository; queue name registered in `jobs/queue.ts` like `reading`.
- Enqueue on receipt: where `PUT /api/files/{id}` completes for a file of kind `audio` (grep the reading enqueue on photo receipt in `storage/`/`sync/`/`http`): one `transcription` job, singleton per audio, retryLimit 3 (three attempts), not started (and audio left as is) while `AI_FEATURES` is off; the audio goes `transcribing` by a `system:transcription` op via `applyServerBatch` (see how the reading job writes system ops and what actor it uses; add `system:transcription` wherever actors are validated).
- Job: load audio from storage -> `SpeechProvider.transcribe` -> kernel level -> prose/report/polish: `WritingProvider.write` with the kernel context -> `writtenTextGuard`; guard fail or write failing for good -> field gets the heard text, run row records why. Prose target: one `applyServerBatch` (audio `done` + both transcripts + `transcription_run_id`, and the put on the target with `meta.source_audio_id`; append or caption replace rule from the kernel). Table target: `parseTableUtterance`; parsed -> pending Suggestion on the cell sourced `{audio_id}`, nothing written to the cell; not parsed -> text to the ficha's Observações as audio text, audio records `not_a_reading`. The target field's permission: a role without it is refused (see AD-29 `permissionForRoute` and how server ops are checked; system ops for a job must not bypass a missing permission of the audio's creator: follow the reading job's precedent and state the choice).
- Third failure: audio `failed` by a system op. `POST /api/audios/{id}/retranscribe`: authenticated, tenant-scoped, permission of the target field, only from `failed` (and `done`? no: only `failed`), re-queues (resets to `queued`/`transcribing` by system op), 404 across tenants.
- Never send another company's data to a prompt; run row on every run; `GET /api/health` unchanged.
- Dismiss is a device op (`audio_status` -> `dismissed`) and must fold on the server; a system-only status written by a device op must be refused (device may write `dismissed` only; `audio_target` and `quality` immutable after create).
