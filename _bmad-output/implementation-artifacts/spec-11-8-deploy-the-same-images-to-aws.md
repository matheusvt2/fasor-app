## Intent

**Problem:** The product runs only in local docker-compose. Story 11.8 (as narrowed by its dated notes in `epics.md:2443-2463`, `source-deltas.md:57-63` and epic-11-context "Coordinator decisions" item 2) needs one lean `production` environment in AWS `us-east-1`, all Terraform in `infra/`, deployed by a shell script, reached over HTTPS from tablet browsers, costed below USD 100/month.

**Approach:** A new Terraform stack `infra/production/` (VPC with a public subnet, one EC2 instance registered to an ECS cluster running three host-network services: api with in-process worker, ocr sidecar, Caddy; RDS PostgreSQL 18 `db.t4g.micro` in private subnets; S3; SSM SecureString; CloudWatch Logs; ECR; night schedule; budget action). A self-contained production api image. A deploy script `infra/bin/deploy` (build, push, one-shot migration task, service roll, HTTPS health). The api learns the AWS default credential chain. No AWS call is made tonight (no login): everything is proven offline.

## Boundaries & Constraints

**Always:**
- Never call AWS: no `terraform plan/apply`, no `aws` command against the account, no deploy run. Offline proofs only (`init -backend=false`, `validate`, `fmt -check`, tflint, shellcheck, deploy `--dry-run`, local image build and run).
- Everything in containers (Terraform `hashicorp/terraform:1.16.4`, aws-cli `amazon/aws-cli:2.37.6`, tflint, shellcheck, docker buildx). Never install on the host. Never register qemu/binfmt on the host.
- Terraform: `required_version ~> 1.16.4`, `hashicorp/aws ~> 6.66` (as in `infra/bootstrap/versions.tf`), any extra provider pinned `~>` and locked in a committed `.terraform.lock.hcl`; `allowed_account_ids = ["673409896745"]`; `default_tags { project = "fasor", managed-by = "terraform", stack = "production" }`; S3 backend bucket `fasor-tfstate-673409896745`, key `production/terraform.tfstate`, `use_lockfile = true`, `encrypt = true`, region `us-east-1`.
- Local compose keeps MinIO with static keys and `S3_ENDPOINT`; behavior of `pnpm verify` unchanged.
- The repo is public: no secret, account key, state, plan or real password in git. Secrets live in SSM Parameter Store SecureString (AWS-managed key), generated by `random_password`.
- No emoji; English code/docs; no Fasor branding in user-visible strings; nothing user-visible changes in the web app.

**Never:** Fargate, ALB, NAT gateway, Secrets Manager, Container Insights, a `staging` environment, CI, a domain, an Auto Scaling group that terminates the instance at night (it would lose Caddy's certificate storage), `force_path_style` against AWS S3, static AWS keys anywhere in production, the root profile `fasor`.

## I/O & Edge-Case Matrix

| Scenario | Input / State | Expected Output / Behavior | Error Handling |
|----------|--------------|---------------------------|----------------|
| Local compose | `S3_ENDPOINT` + both static keys set | S3 client with endpoint, `forcePathStyle: true`, static credentials; `ensureBucket` creates bucket + versioning (today's behavior) | none |
| AWS | `S3_ENDPOINT`, `S3_ACCESS_KEY_ID`, `S3_SECRET_ACCESS_KEY` unset | S3 client with only `region`, no `credentials` (SDK default chain: ECS task role), virtual-hosted style; boot only probes the bucket (`HeadBucket`), never creates it nor changes versioning | probe retried like today, then boot fails |
| Half keys | exactly one of the two keys set | `loadConfig` throws `ConfigError` naming the missing one | exit 1 at boot |
| Empty strings | keys or endpoint set to `''` (compose `${VAR:-}` style) | treated as unset | same as AWS row |
| Deploy dry run | `infra/bin/deploy --dry-run` without AWS login | prints every step's command with placeholder outputs, exits 0, no docker push, no aws/terraform call | none |
| Deploy real, dirty tree | uncommitted changes | refuses before building | exit non-zero with a message |
| Migration fails | migrate task exit code != 0 | deploy stops before the service roll; prints the CloudWatch log stream name | exit non-zero |

## Design Notes

- Architecture default `x86_64`: the coordinator chose Graviton, but the ocr sidecar's pinned `paddlepaddle==3.3.1` has no linux aarch64 wheel, so "the same images" cannot run on arm64. `var.architecture = "arm64"` switches instance type, AMI and build platform in one line once the ocr image builds for arm64 (or ocr is disabled). Open question for Matheus; cost delta about USD 2-3/month.
- Night stop keeps the EBS root (Caddy's ACME account and certificate, cached images) and the EIP; ECS re-places the tasks when the instance reconnects at 05:00 (a few minutes of backoff is expected).
- Host network mode: Caddy reaches the api at `127.0.0.1:3000`, the api reaches ocr at `127.0.0.1:8000`; only 80/443 are open. Rolls stop the old task before starting the new one (seconds of downtime, acceptable for at most 10 users).
- Secrets: `random_password` lands in the encrypted private state bucket (not in git); stated in the README.
