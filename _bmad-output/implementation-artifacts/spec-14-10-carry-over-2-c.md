## Intent

**Problem:** A production deploy is proven only by `GET /api/health` and a person's hand check (the 2026-10-15 check ran on Bruno's account). Nothing exercises the real flows (sync, photo upload, a plate reading, the document) after a roll, and no account exists that a test may write to in production (`deferred-work.md` line ~2226, open, owner Matheus; Matheus decided option (a) on 2026-10-15).

**Approach:** Terraform declares a dedicated test company and user (fixed company id and e-mail as variables, the password generated by `random_password` and kept in AWS Secrets Manager) and a one-shot ECS task `smoke-seed` (api image) that resets that company alone and re-seeds it (user, standard template, one fresh test relatório from the small Porto Seguro sample). `infra/bin/deploy`, after a green health check and the tag record, runs `smoke-seed`, then a short Playwright suite under `e2e/production/` in the tools container against the deployed URL signed in as that user, then `smoke-seed` again as the cleanup (always, also after a failed smoke), and exits non-zero naming the failing step when the smoke failed. No automatic rollback.

## Boundaries & Constraints

**Always:**
- Every write of the seed/reset touches rows whose `company_id` is the smoke company only; the CLI refuses a company id that is not a uuidv7, and refuses a company that holds any user other than the smoke e-mail (so a misconfigured id can never wipe a real company). `seedUser` already refuses an e-mail owned by another company.
- The reset deletes the smoke company's `ops`, `entities`, `sync_device_push` and `reading_runs` rows (the `resetTestCompanyData` table set, `apps/api/src/db/seed.ts:520`), then re-seeds `seedUser` (password from `SMOKE_USER_PASSWORD`, which revokes old sessions), `seedStandardTemplate` and `seedSampleRelatorio`. S3 objects the run uploaded stay: production has no delete (AD-7, task role has no `s3:DeleteObject`); state it in the README cost table.
- The password reaches the task only through the task definition's `secrets` (Secrets Manager ARN), never an environment override or a command argument (E11-A4); the deploy reads it with `infra/bin/aws secretsmanager get-secret-value` into a shell variable and passes it to the container by name (`-e SMOKE_PASSWORD`, value from the environment), never on a command line, never printed (dry run prints `<secret>`).
- The production suite is excluded from every local command: it lives in `e2e/production/*.smoke.ts` with its own `e2e/production/playwright.config.ts` (`testMatch: /\.smoke\.ts$/`, no webServer, no globalSetup, one worker, no retries, base URL from `SMOKE_BASE_URL`, credentials from `SMOKE_EMAIL`/`SMOKE_PASSWORD`, it fails fast naming any missing variable). The root `playwright.config.ts` default testMatch never matches `.smoke.ts`; `scripts/e2e.test.ts` (or a new tooling test) asserts the root config lists none of them.
- At most one real plate reading and no emission audit per run. When `GET /api/account` answers `features.ai = false` the plate step is reported as skipped (a printed line), not failed.
- Infra changes are Terraform in `infra/production/`, `terraform fmt`-clean and passing `infra/bin/check` (validate, tflint, ShellCheck).
- Deploy order stays: preflight, outputs, build, push, migrate, roll, health, record, then the new steps: `smoke: reset the test company`, `smoke: run the production suite`, `smoke: clean up the test company`. The smoke takes the host lock when `lockf` or `flock` exists (`/tmp/fasor-verify.lock`, wait up to 30 min, AGENTS.md: no Playwright run outside the lock), and runs without it, saying so, when neither exists.

**Never:**
- No `apply`, no `infra/bin/deploy` real run, no AWS write from this batch; `infra/bin/tf production plan` and read-only `infra/bin/aws` only.
- No change to `packages/domain` progress/counts, Home cards, Sumário, `nameplate-suggestions.tsx`, `components.css`/`app.css`, DESIGN.md (batch co16b). No contract bump (stays 20). No new always-on AWS service.
- The smoke never runs in `pnpm verify`, the story gate, `test:e2e*`, or `test:unit` as a browser test.
- No automatic rollback (open question Q-1 below).

## I/O & Edge-Case Matrix

| Scenario | Input / State | Expected Output / Behavior | Error Handling |
|----------|--------------|---------------------------|----------------|
| Seed fresh | smoke company absent | company, user, template, sample relatório created; prints ids, never the password | -- |
| Seed again | company holds last run's edits, photo, revision | all its ops/entities/push/reading_runs gone, re-seeded to the same state; other companies' rows byte-identical | -- |
| Wrong id | `SMOKE_COMPANY_ID` names a company with another user | exit 1 "refusing: company X holds users other than <email>", nothing written | -- |
| Bad id | not a uuidv7, or a variable missing | exit 1 naming it, before the database is opened | -- |
| Smoke green | deploy healthy | prints each step passed, the reading count, the DOCX/PDF sizes; deploy exits 0 after the cleanup | -- |
| Smoke red | any step fails | cleanup still runs; deploy prints "smoke failed at step: <name>", the report path, and "to roll back: infra/bin/deploy --skip-build --tag <previous tag>"; exit 1 | cleanup failure is printed too and also exits 1 |
| Dry run | `--dry-run` | the three smoke steps print `DRY-RUN:` lines; `DEPLOY_DRY_RUN_SMOKE_EXIT=1` exercises the red path (failure message, cleanup still printed, exit 1) | -- |
| `--skip-smoke` | operator flag | the smoke steps print "skipped by --skip-smoke" | -- |
| AI off | `features.ai = false` | plate step skipped with a line; other steps run | -- |

- `infra/bin/deploy` -- smoke steps, `--skip-smoke`, failure report, rollback hint, cleanup always, lock.
- `e2e/production/*` and `package.json` -- the suite: steps named `1. sign in and open Home`, `2. open the test relatório`, `3. edit a value and sync`, `4. add a sheet photo`, `5. read the plate`, `6. preview the PDF`, `7. generate a revision`, `8. download DOCX and PDF`; each `test.step` appends its name to `test-results/production-smoke/progress.txt`. Assert committed state, not only the screen: the synced edit (Sync status 0 pending after "Sincronizar agora"), the photo held by the server (its upload state), the reading done with N fields read (printed), the DOCX starts with `PK` and is over 10 KB, the PDF starts with `%PDF` and is over 10 KB.
- `scripts/deploy.test.ts`, plus a tooling assertion that no `*.smoke.ts` is collected by the root Playwright config -- tests.
- docs and ledgers as in the Code Map.

**Acceptance Criteria:**
- Given `infra/bin/deploy --dry-run`, when it runs, then the steps after `record` are `smoke: reset the test company`, `smoke: run the production suite`, `smoke: clean up the test company`, each printing its DRY-RUN command, and no line holds a password.
- Given `DEPLOY_DRY_RUN_SMOKE_EXIT=1 infra/bin/deploy --dry-run`, when it runs, then the cleanup step still prints, the output names the failing step and the rollback command with the previous tag, and the exit code is 1.
- Given the tools container, when `pnpm exec playwright test -c e2e/production/playwright.config.ts --list` runs, then it lists the one smoke test; when `pnpm test:e2e -- --list` (root config) runs, then no `.smoke.ts` appears.
- Given `infra/bin/check`, when it runs, then fmt, validate, tflint and ShellCheck pass.
- Given `infra/bin/tf production plan`, when it runs, then it adds only the smoke resources (secret, version, random password, task definition, log group, IAM statement change) and replaces nothing.

## Design Notes

Open questions (dated, for the PR body and the epics line):

Fixed: Secrets Manager USD 0.40 a month plus API calls (USD 0.05 per 10 000). At 30 deploys a month: under USD 0.80 in all; the README total moves from 82.52 to about 83.3.
