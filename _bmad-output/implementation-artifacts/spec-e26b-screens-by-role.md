## Intent

**Problem:** Epic 26 batch e26a made the kernel and the server role-aware (`packages/domain/src/permissions/`: `can`, `keysOf`, `permissionForPath`, `permissionForRoute`, `activeUser`; role rows and the user's `role_id`/`status` reach IndexedDB by the company pull; `localRoleOf(db, userId)` in `apps/web/src/db/sync-store.ts`). The app still shows every user every module.

**Approach:** One provider that reads the signed-in user's role from IndexedDB (live, so a pull changes the screen with no reload) and answers the kernel's `can`; one hook; one route guard fed by a kernel map of screen to key. Hidden: shortcuts, routes, menu entries of a module the user lacks. Disabled with one reason line: controls inside a screen the user does use. Read-only ficha without `relatorio.fill`. After sign-in, return to the asked address.
