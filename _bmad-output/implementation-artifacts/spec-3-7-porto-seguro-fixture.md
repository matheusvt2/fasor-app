## Intent

**Problem:** Every renderer/Sumário/pre-issue test from Epic 4 onward needs a real, fully-populated relatório to run against, and none exists yet — only the seeded template (Story 3.1/3.2, PR #18) and small synthetic fixtures (`replay-small`) are on hand.

**Approach:** Author `packages/domain/fixtures/porto-seguro/` as a second op-log fixture built with the exact same harness as `packages/domain/fixtures/replay-small/op-log.ts` (that file's own header comment already says the Porto Seguro log is "the second input of the same harness"): a typed per-block data file transcribed from the delivered FO.SERV-03 (`docs/context/FO.SERV-03 Laudo Técnico de Cabine Primária.docx`, copied read-only into this worktree since it is gitignored — never commit it) and from `_bmad-output/planning-artifacts/prds/prd-fasor-2026-09-19/.working/extract-raw-sources.md` §1-2, turned into a fixed-id/fixed-timestamp `Op[]` log the same way `replay-small` is, plus a small second fixture (one cabine, three blocks) for lighter tests. No kernel schema or op-path change is needed — `project`, `relatorio`, `location`, `equipment`, `block` (create) and every `sheet/*` field family (`nameplate`, `checklist`, `test`, `test/cell`, `conclusion`, `observations`), plus `point` and `file` (photo), already exist in `packages/domain/src/ops/path.ts` and `schemas/entities.ts` — confirmed by direct inspection before writing this spec (process lesson (c)).

## Boundaries & Constraints

**Always:** every op carries a fixed `op_id`/`client_ts` derived from a per-fixture numeric index (mirror `replay-small`'s `fixedId(n)`/`fixedOpId(n)`/`fixedTs(n)`, but with a distinct hex prefix, e.g. `019966c0-...`, so ids never collide with `replay-small`'s `019966b0-...` if both fixtures are imported in the same test file); the generator is a pure function of its typed data file (no `Date.now()`, no `Math.random()`, no `crypto.randomUUID()`) so two runs byte-diff identical and `replay(log)` is stable; real Porto Seguro client data (client name, CNPJ, site, people, TAGs, serials, dates, coordinates, measured values, photo captions) is written only under `packages/domain/fixtures/porto-seguro/` and nowhere else in the tracked tree (waiver R-023, AGENTS.md); the location skeleton and per-column equipment quantities mirror `standardTemplate()`'s own skeleton/blocks output (`packages/domain/src/seed/template.ts`) exactly — the fixture is that same 94-block distribution (25 chave_seccionadora, 21 disjuntor_mt, 11 tp, 11 tc, 8 transformador_forca, 4 cabos_entrada, 9 cabos_saida, 5 para_raio) with real per-instance data laid over it, since the standard template was itself modeled on this delivered job; checklist result cells are left unset (no `sheet/checklist/{item}/result` put) wherever the source is genuinely blank — the extract confirms **zero C/NC/NA marks across all 94 sheets** — do not invent marks; the two untested chave_seccionadora units plus the TIE disjuntor_mt (section 8, bullet 4) get a `block/{id}/not_tested` put (`reason: 'Solicitação do cliente'` per the bullet's wording) instead of measured test cells; unmeasured numeric cells (`30 SEGUNDOS`, `ESTAB./10MIN`, absorção, polarização — printed `-`) use `{raw: '', unit, state: 'not_measured'}` exactly like `replay-small` line 261; a second, small fixture (one cabine, three blocks, e.g. reusing the `disjuntor_mt`/`chave_seccionadora`/`transformador_forca` triad already used in `replay-small`'s own three blocks for consistency) lives under the same `packages/domain/fixtures/porto-seguro/` tree (a `small/` subfolder) so it stays inside the waiver's path and is real-data-optional (synthetic values are fine there, it exists only for tests that don't need the full 94).

**Never:** do not touch `packages/domain/src/ops/path.ts`, `schemas/entities.ts` or any op family — every entity/path this fixture needs already exists; do not add a renderer, DOCX/PDF golden document, or any Epic 6+ surface — those don't exist yet (lesson (c)), the "golden documents" the waiver anticipates for this path are for a later epic, this story's golden artifact is the JSON snapshot only; do not implement `instantiateTemplate` (Story 4.1) — hand-construct the ops directly, optionally reading `standardTemplate()`'s output structurally (skeleton refs, `TemplateBlock.quantity`/`skeleton_location_ref`) to derive the fixture's location/equipment/block shape, but the fixture's own generator owns its ids and values; do not copy the DOCX or any `docs/context/`/`docs/media/` file into a tracked path — read it locally (already copied to this worktree's gitignored `docs/context/`) and transcribe values into the typed data file only; do not add a UI-facing test — this is kernel/test-only (no `apps/web` surface change beyond a Dexie-load test, no Playwright).

## Design Notes

**Id/timestamp namespacing.** Use a hex prefix distinct from `replay-small`'s `019966b0` (e.g. `019966c0` for the full fixture, `019966c1` for the small one) so both fixtures can be imported side by side in the same test file without id collisions — `fixedId`/`fixedOpId`/`fixedTs` otherwise copy `replay-small`'s exact zero-padding scheme.

**Reusing `standardTemplate()`'s shape.** Rather than re-deriving the 6-cabine/94-block skeleton by hand, call `standardTemplate({id: fixedId(...)})` (or read its source constant if it isn't parameterizable the way you need) to get the exact skeleton refs and per-column `TemplateBlock[]` (`quantity`, `skeleton_location_ref`, `BlockConfig`). Expand each `TemplateBlock` into `quantity` concrete block/equipment/location-linked instances with fixed ids assigned by a stable, documented ordering (e.g. skeleton order, then block-type declaration order, then instance index) so a re-run is reproducible; then overlay each instance's real per-item data (TAG, nameplate, checklist, tests, conclusion, not_tested) from `data.ts`, matched by `(skeleton_location_ref, block_type, instance_index)`.

**Not-tested wiring.** Per section 8 bullet 4, the 2 chave_seccionadora and the TIE disjuntor_mt get `block/{id}/not_tested` = `{reason: 'Solicitação do cliente', text: <bullet 4's own sentence, trimmed to the block's relevance>, at: <fixed ts>, by: <fixed actor>}`, no `sheet/test/*` puts, and a matching `point/{id}` create with `origin: 'not_tested'` (the schema field exists for exactly this; no derivation code exists yet elsewhere in the repo, so the fixture hand-builds both sides, same as `replay-small`'s one manual `point` row).

**Instrument registry.** Create the 3 instruments as `registry/instrumento/{id}` rows (kind from `registryKindSchema`) before referencing them from `sheet/test/{test_key}/instrument` cells; store the referencing cell's `value` as the instrument's row id (uuidv7), per the epic-3-context Technical Decisions note that instruments are referenced by id, not by value.

**Section 7 photos.** One `file` create per numbered image (01-76, with the 75/76 defect reproduced 4 times each per the source), `kind: 'photo'`, placeholder `sha256`, real caption text, no `block_id` link required unless a caption clearly names an equipment (most don't); this is metadata-only, matching the one existing precedent in `replay-small`.
