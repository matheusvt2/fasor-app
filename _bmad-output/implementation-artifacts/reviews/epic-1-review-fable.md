Scope: everything on `main` at `00de851` delivered by PRs #1-#8 (Stories 1.1-1.8), reviewed read-only against `AGENTS.md`, `ARCHITECTURE-SPINE.md` (AD-1..AD-27), `epics.md` §Epic 1, the eight specs, `epic-1-context.md`, `test-design-qa.md`, the handoff, the manual script and the PR review comments. Commands run from the main checkout: `docker compose run --rm tools pnpm lint` (exit 0, 60 s wall), `pnpm static` (exit 0, 51 s), `pnpm test:unit` (exit 0, domain 22 files / 273 tests, web and scripts green, 165 s wall including container start), plus `git log`, `git show`, `gh api` for the PR comments. No `docker compose up/down`, no api or e2e run, no DB touched.

## Executive summary

1. Epic 1 delivers a coherent offline-first foundation: op log, single reducer on both sides with a byte-equal replay golden, origin-aware sync with per-op rejection, per-user Dexie store with four append-only versions, service-worker shell with a page-owned activation gate, drafts, eviction recovery and a Home/Account pair whose every line comes from the kernel.
2. Lint, static and unit are green on `main` today; `pnpm verify` is the real merge gate and was pasted in every PR (238 s at the last story).
3. Architecture conformance is high: `fetch` only in `src/sync` and `src/api`, Dexie only in `src/db`, `company_id` on every table, contract-typed sync routes, kernel-only status/count/text with a handful of small leaks.
4. Two concrete traps need fixing before Epic 2 starts: the seed CLI accepts a v4 company id while `opSchema` requires uuidv7 for `company_id` (a company provisioned with the documented example id can never sync), and `commitBatch` still takes `device_id` from the caller with no minted default.
5. Cross-story seams are the main debt: Login, the registration dialog and the sign-out dialog still carry hand-rolled markup (a second radiogroup and a second confirm dialog beside the 1.2 components), pt-BR status labels exist in the kernel and in `copy/ui.ts`, and three 1.2 controls (Toggle, Checkbox, grouped FilterChip) still never show their on state.
6. Test quality is good where it matters (live-container API suites, six named durability scenarios, "Sincronizar agora" instead of timers) but the cross-browser matrix, `pnpm audit` and coverage floors are outside `pnpm verify`, and the WebKit offline reopen is only covered by the manual iPad script, which has not run.
7. Security posture is sound for a LAN MVP (httpOnly/Lax/Secure cookie, pinned `baseURL`, sign-up off, tenant-scoped dedupe, SW never caches `/api`); rate limiting is off because `NODE_ENV` is unset and the dev server is exposed on all interfaces.
8. The deferred ledger `deferred-work.md` holds two items while the eight specs carry 34 `deferred` entries; a dozen are already closed by later stories and nobody marked them.
9. The internal 4-layer review found ~310 findings and patched ~117; the independent reviews still caught two highs (Combobox `aria-disabled` dropped by react-aria, Tema keyboard semantics) and three design-level gaps (coalescing vs attribution, hold-shell, tenant-scoped dedupe): diff-only, context-free reviewers miss runtime library behaviour and spine-level interactions.
10. Verdict: accept the epic with the action list in §8; the PRD Q0 manual proof on the iPad is the only open gate before capture work.

- Spec quality. Seven of eight specs carry `warnings: ['oversized']` (all but 1.1); they run 190-440 lines with Code Maps that cite file and line numbers, which gave the implementation subagents precise anchors and is visibly why the diffs land on the architecture's shape. Findings per story: 1.1 about 31, 1.2 35, 1.3 51, 1.4 39, 1.5 39, 1.6 43, 1.7 30, 1.8 42 (about 310), highs only in 1.7 (3, one root cause) and 1.8 (3); patched 7, 9, 18, 22, 17, 21, 12, 11. ## 8. Verdict

Top 5 strengths
1. The kernel is genuinely the single source of truth: one reducer, one materializer on each side, a committed golden, and Home/Account/Sync rendering strings the kernel wrote (`packages/domain/src/home/cards.ts`, `sync/counts.ts`).
2. Sync semantics are right and tested where they bite: per-op atomicity, origin spoof rejection, tenant-scoped dedupe, rebase and dead-op exclusion from one `materializeEntity`, 426 on pulls only, all against a live Postgres.
3. The offline vehicle is honest: shell-only precache, page-owned activation and hold, all-or-nothing install, drafts never applied silently, eviction recovery that survives a reload, refused writes surfaced.
4. Boundaries are enforced mechanically: import direction, `fetch` sites, Dexie sites, byte-identical mock CSS, drift test for migrations, determinism scan, codename scan.
5. The review chain caught real defects before merge and recorded every rejection with a reason; the PR bodies paste `pnpm verify` output as the policy requires.

Top 5 weaknesses
1. Pre-1.2 surfaces (Login, registration dialog, sign-out dialog) still hand-roll inputs, buttons, a radiogroup and a confirm dialog beside the shared components, and three shared controls still have no visible on state.
2. Two traps for the first real company: a v4 company id passes the seed CLI but fails `opSchema`, and committed ops carry whatever `device_id` the caller passes.
3. The PRD Q0 manual proof has not run; Safari's offline reopen, the Secure cookie over the tablet HTTPS origin and the Tema keyboard on iPadOS are unverified, and the storage threshold is a guess.
4. `pnpm verify` gates less than the test design assumes (no matrix, no audit, no coverage) and the main checkout's `tools` image cannot run the matrix.
5. Debt bookkeeping: 34 spec deferrals, 2 ledger entries, about a third already closed and unmarked; several AD-2 text and policy leaks and a duplicated status vocabulary went unnoticed because each story reviewed only its own diff.
