## Intent

**Problem:** The relatório can be captured but never leaves the system: no job freezes a snapshot, builds the FO.SERV-03 document, converts it with LibreOffice, numbers a revision or serves the DOCX, and the Export dialog does not exist. Story 4.8 (`_bmad-output/planning-artifacts/epics.md` "### Story 4.8", ACs verbatim there) proves the one renderer end to end on the seeded template before sheets, photos and points are added.

**Approach:** A pure kernel layout spec (`packages/domain/src/print`) turns a `RelatorioSnapshot` into the printed document's data (header, footer, cover, document control page, static TOC entries, sections 1 to 11); `apps/api/src/jobs/generate` renders it with the `docx` library, converts its own DOCX to PDF with LibreOffice headless (concurrency 1, per-job profile), writes the TOC in two (at most three) passes from the PDF outline, and stores both files plus the `revision` op in one transaction; `POST /api/relatorios/{id}/generate` is the flush barrier (`409 not_caught_up`) and `GET /api/revisions/{id}/docx` the download; the web Export dialog (mock `73-exportar.html`) flushes, requests, polls the pulled `generation_job`/`revision` rows and emits the two status ops through `statusTable`. The Sumário (Story 4.3, another batch, in parallel) is NOT built here; the dialog is exported as a component and mounted, for tests, by a dev-only fixture route.

## Boundaries & Constraints

**Always:** kernel ownership (AGENTS.md, AD-1 to AD-3, AD-13): every printed string, row, order, revision number, "Rev. n"/"Gerando revisão n…"/revision-row text, `file_ids_expected`, and the status transition come from `packages/domain`; `apps/api` only renders the layout spec, runs the job and applies ops; `apps/web` renders from IndexedDB and writes only ops into the outbox. The snapshot is frozen once per job (`toSnapshot` under the company advisory lock together with `snapshot_seq = max(ops.seq)` of that relatório's stream) and is the only input of the renderer. The revision `number` is allocated inside the one transaction that applies the two `file` creates, the `revision` create, `generation_job/{id}/status = done` and `generation_job/{id}/result`; a failed job applies only `generation_job/{id}/status = failed` and `generation_job/{id}/error`, allocates no number, creates no `file` row (S3 objects written before the failure are orphan-safe: immutable keys, never referenced). Generation dates appear only in the two named layout fields (document control "Data de emissão" and the revision line) and the renderer takes `issuedAt`/`revisionNumber` as inputs, so the golden test is deterministic with a fixed clock. pt-BR copy: printed labels verbatim from FO.SERV-03/the ACs, dialog copy verbatim from `73-exportar.html`, anything else marked `// authored:`; no emoji; `relatorio` never `laudo`; the product name only through `PRODUTO`. LibreOffice stays in the api image (`apps/api/Dockerfile`, already at 26.2.6 with Liberation/DejaVu/Carlito/Caladea fonts); `GET /api/health.libreoffice` keeps its truthful `soffice --version` probe. Docker only: every install/test command runs in the compose project `fasor-e4d` from the worktree root (`docker compose --profile tools run --rm tools pnpm …`; `pnpm add` inside the `tools` container so `pnpm-lock.yaml` updates before `install --frozen-lockfile`). New `.frame-*` mock rules the dialog renders get their `app.css` translation with the mock-naming comment.

**Never:** no Sumário, no tree, no setup page, no "Pré-visualizar", no pre-issue list rows ("Parecer não preenchido", "N avisos"), no read-only document control table inside the dialog (FR-73, Epic 7), no share buttons, no PDF row or PDF download (Epic 11, slice item 2), no watermark/preview kind, no section 9 content, photos, points or certificates (Epics 6 and 7), no `last_nameplate` projection (AD-25, Epic 7), no rich text. Never install LibreOffice in `Dockerfile.tools`; never run soffice on the host; never read `NODE_ENV === 'production'` fault flags; never retry a failed job automatically (`retryLimit: 0`); never let the server write `relatorio/status`; never derive a status, count or text in `apps/*`; never copy client material outside `packages/domain/fixtures/porto-seguro/`; never edit `sprint-status.yaml`, `epics.md`, or the planning documents.
