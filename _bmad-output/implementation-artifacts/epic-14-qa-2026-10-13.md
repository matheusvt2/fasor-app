**Q-2, should-fix. Reordering points goes wrong while a removed local holds a site point.** 14.2 x 14.3.
Scenario: site point H created first, then manual points A and B; remove the local; the list shows A (1 de 2), B

## 4. Recommendations on the three open items

**R-1, 14.5 R1 (whole `block/{id}/config` put, last writer wins): defer the per-key family to the architect
(contract 20, before Wave 3); add the cheap signal now.** The web already re-reads and merges the fresh config
inside the edit, so the window is two devices offline at once. Scenario: A sets polos 4 and types the N rows, B on
polos 3 switches E6 off and syncs later: B's config stands (polos 3, E6 off). No value is lost (hidden cells stay
stored and writable), but the document prints 3 poles, the N rows are not required or printed, and verdicts can
move; the only signal is the generic "alteração … mantida (a mais recente prevalece)". Now: name the changed config
keys in that merge line (`packages/domain/src/merge/info.ts:37`, `:329`), no new path.

**R-2, 14.2 (h) (sheet stranded under a location removed before the newest revision): fix now, kernel only.**
Confirmed: the sheet is live, hidden by `snapshot.ts:105`, offered by neither `restorableEntries` (not removed)
nor its location (before the cut, `sumario.ts:601`), and its route says not found; the data is unreachable, not
lost, and api totals and Home disagree (ledger g). Fix: list every live block on a hidden location as its own
entry regardless of the cut, restored by putting back only its removed ancestors (`removedAncestorIds`,
`removal.ts:147`). Keeping the whole location past the cut is less safe: its plan would also bring back sheets the
issued revision excluded. Treat Q-8 (site answers on such a local) the same way.

**R-3, 14.3 O3 (NC site items absent from "NC abertos"): fix the cheap part now, leave the counter to Matheus.**
Now, kernel only: a pending pre-issue row for site items answered NC with no observation, and a site NC counted as
a restriction in the parecer suggestion (Porto Seguro is v1, the goldens do not move). Matheus: whether site NCs
enter `Progress.nc_open` and the "NC abertos" list. Leaving it lets a relatório be issued with a site
non-conformity, no observation, no point and a clean parecer suggestion (Q-4).
