## fasor

Conforme (codename fasor): a tablet-first, offline-first web app that captures medium-voltage substation test sheets on site and generates Fasor Engenharia's FO.SERV-03 relatório as DOCX and PDF. It is built and in production on one AWS stack.

- Stack: a pnpm 12 monorepo with a pure zod domain kernel in `packages/domain`, React 19 + Vite 8 + Dexie in `apps/web`, Hono 4 + Drizzle + PostgreSQL 18 + pg-boss in `apps/api`, an OCR sidecar in `services/ocr`, everything in docker-compose.
- Planning is BMAD output under `_bmad-output/`; the build contract is `_bmad-output/specs/spec-fasor/SPEC.md` with its companions.
- This file states only what is in force today. The superseded wording, with its dates, is in `AGENTS-history.md`.

## Policy

- **Public repository.** Never copy client material from `docs/context/` or `docs/media/` (gitignored), or the third-party names, CNPJs and coordinates in `docs/concorrentes/`, into tracked files; cite by path. The one exception is the Porto Seguro test fixture (`packages/domain/fixtures/porto-seguro/`) and its golden documents (see "Decisions of record", 2026-09-21).
- **Docker only.** Everything runs through docker-compose; never install or run a service natively on the machine. Development and every test run locally; production is the one AWS stack in `infra/`.
- **No cloud dependency locally.** Local development and the tests never depend on a cloud account or a paid API key; `LLM_PROVIDER` and `OCR_PROVIDER` default to `fake`. The backend never uses a personal Claude subscription.
- **AWS cost.** AWS spend for the whole project stays below USD 100 per month, all services and environments included (compute, database, storage, network, logs, Bedrock, Textract). Every infrastructure choice is costed against this ceiling before it lands, and `infra/` carries an AWS Budget that alerts before the ceiling.
- **No emoji anywhere:** UI strings, documents, mocks, code, commit messages, chat replies and agent persona prefixes. Icons are SVG sprite symbols or CSS glyphs.
- **Product name.** The user-visible name is `Conforme`, the value of the constant `PRODUTO` in `packages/domain`. The codename `fasor` and Fasor branding never appear in a user-visible string, document or file name. The one exception is the sender address of the app's e-mails (see "Decisions of record", 2026-11-21).
- **BMAD files.** `_bmad/` and `.claude/skills/bmad-*` are regenerated by the BMAD installer; overrides go in `_bmad/custom/` only.
- **Branches and pull requests.** Main receives only merged pull requests, self-approved and merged by the author. A wave's stories go in one batch and one pull request (see "Decisions of record", 2026-11-12).
- **No CI.** Lint and tests run locally before the merge; a pull request carries the output of its gate. What a batch runs and what runs once per wave is under "Running and verifying".

## Running and verifying

The detail of every line (lanes, groups, single specs, reports, podman) is in `docs/TESTING.md`.

- **Start the stack:** `docker compose up -d` starts web (Vite, `:5173`), api (Hono on Node 24, `:3000`), PostgreSQL 18 (`:5432`) and MinIO (`:9000`/`:9001`), plus the one-shot `install` and the `mkcert`/`caddy` services (HTTPS origin for tablets, `docs/tablet-https-setup.md`). `GET /api/health` returns `{status, db, queue, storage, libreoffice}`.
- **Never on the host.** Every lint and test command runs inside the `tools` container: `docker compose --profile tools run --rm tools pnpm <script>`.
- **The full gate** is `docker compose --profile tools run --rm tools pnpm verify` (`scripts/verify.ts`), in three phases: `lint`, `static` and `test:api` together, then `test:unit` alone, then `test:e2e` alone (Playwright tagged `@p0`). The first failure stops its phase and every later one. Logs: `test-results/verify/`.
- **A batch runs, before its pull request,** with the output pasted in it: `lint`, `static`, `test:unit`, `test:api:batch` and the Playwright specs it touched. When it changes the op fold, the commit path or a live query on the ficha, it also runs its touched durability specs on the matrix projects.
  - Api suite, from the worktree on the host: `docker compose --profile tools run --rm --user node -e API_CHANGED_FILES="$(git diff --name-only origin/main...HEAD; git diff --name-only HEAD; git ls-files --others --exclude-standard)" tools pnpm test:api:batch`.
  - Touched specs: `docker compose --profile tools run --rm tools pnpm exec tsx scripts/e2e.ts <specs> --project desktop-chrome --project durability-desktop-chrome`.
- **Once per wave, on the integrated branch,** the coordinator runs one full gate: `lint`, `static`, `test:unit`, the plain `pnpm test:api`, `pnpm test:e2e:full` and `pnpm test:e2e:matrix`. It runs again at the epic QA. A red wave gate becomes a fix batch before the next wave.
- **Api lanes** (`apps/api/src/test-lanes.ts`, run by `scripts/api-suite.ts`): `api-solo` first, alone; then the parallel lane `api` on 4 workers beside `api-serial` then `api-print`, one file at a time. A new api test file that reaches a shared resource goes in a lane, or `scripts/api-suite.test.ts` fails. Logs: `test-results/api-suite/`.
- **E2e groups** (`e2e/support/groups.ts`, run by `scripts/e2e.ts`): the parallel group on 2 workers, then the `queue` lane on 2 workers (specs that share the document or reading queue), then the `solo` lane on one worker (specs that time a tap or a wait against a render). All three always run. A new serial spec is listed in `SERIAL_SPECS` with its lane. Report: `test-results/e2e-report/summary.json`.
- **Timeouts:** a Playwright action gives up after 15 s and a navigation after 30 s (`playwright.config.ts`).
- **One gate at a time.** Wrap `verify`, `test:e2e:full`, `test:e2e:matrix` and any multi-worker or Playwright run in the host lock, `flock /tmp/fasor-verify.lock`. At most two batch stacks are up at a time, and the main checkout's stack is stopped (`docker compose stop`, never `down -v`) while batches run.
- **OCR sidecar** (`services/ocr`, port 8000): under the `ocr` compose profile, never started by a plain `docker compose up -d`. `docker compose --profile ocr build ocr`, then `docker compose --profile ocr run --rm ocr pytest`; outside `pnpm verify`, under the host lock, only for work touching `services/ocr` or its contract. Its JSON Schema is exported with `pnpm schema:ocr`; a `test:unit` test fails when the committed schema drifts.
- **Not in the gate:** `pnpm audit --prod`; known advisories are tracked in `_bmad-output/implementation-artifacts/deferred-work.md`.
- **Tool versions:** Node 24 LTS, pnpm 12, TypeScript 6.0, Vitest 5, Playwright 1.63 (spine § Stack).
- **Nothing ships untested:** every implemented feature is exercised end to end, and a feature with a front end runs through Playwright as a human would, covering the whole feature, not a sample.

## Conventions that differ from defaults

- When planning documents disagree: `source-deltas.md` wins, then the architecture spine, then `EXPERIENCE.md` and `DESIGN.md`, then `prd.md`.
- Never delete or silently rewrite a sentence in a planning document: strike the old text through, add the new one beside it with the date, and keep the reading order above. This file is the one exception (see "Decisions of record", 2026-11-28).
- Code, comments, commit messages and every new document are English; the domain words below, the pt-BR UI copy and the existing Portuguese READMEs are the only exceptions.
- A story is ready to build only with acceptance criteria, a definition of ready and a definition of done written in `epics.md`; implementation stays inside what the story says.
- The deliverable is a relatório: code, routes, paths and UI say `relatorio`, never `laudo`. Identifiers are English with the domain words `relatorio`, `cabine`, `ficha`, `parecer` kept; UI copy, stored labels and the generated document are pt-BR verbatim from FO.SERV-03.
- Screens are built from the mockups with the mock's class names; `tokens.css` and `components.css` are copied unchanged into `apps/web/src/styles`; behavior comes from React Aria Components; no Tailwind, no component kit with its own theme. `DESIGN.md` and `EXPERIENCE.md` win over a mock on conflict.
- Ownership (AD-1 to AD-3, AD-13): `packages/domain` is pure TypeScript and computes every status, count, text, order and verdict once; `apps/web` renders only from IndexedDB and writes only ops into the outbox; `apps/api` applies ops and renders documents; `applyOp` is the only reducer on both sides. Nothing in `apps/*` derives a status or count from a sheet.

## Where a new user-facing string goes (kept outside the managed block)

Decided 2026-09-22 (Epic 1 retro A7). pt-BR copy has three homes, and each string lives in exactly one:

- **Derived text goes in `packages/domain`.** This means anything computed from data: status words (`statusLabel`), counts and plurals (`plural`, `relatoriosCount`, `pendingSummaryText`, `rejectedText`), and composed rows (`registrationRowText`, `storageLine`, `serverHoldsText`). `apps/web` never writes a singular-or-plural choice, a status word or a rule such as "which statuses are pulled" (`isAutoPulled`) of its own.
- **Static surface copy goes in `apps/web/src/copy/pt-br.ts`.** These are headings, labels, notes, button words and fixed sentences of one surface, verbatim from the mocks or marked `// authored:`.
- **Component chrome goes in `apps/web/src/copy/ui.ts`.** These are the words a shared component owns whatever screen it is on ("Ativado", "Cancelar", the overflow trigger's label template).

## Mock container selectors (kept outside the managed block)

Decided 2026-09-22 (Epic 1 retro A5, F-PAT-2). This extends "Conventions that differ from defaults". The mocks draw every screen inside a device bezel, so `components.css` encodes the base scope and the viewport as container classes that the app never renders. `tokens.css` and `components.css` stay byte-identical; each translation goes in `apps/web/src/styles/app.css` with a comment naming the mock rule it mirrors, declarations copied verbatim:

- `.frame, .frame *` and `.frame X` base rules become `:root` scope (`:root`, `:root *`, or the bare element), so React Aria overlays portaled to the end of `<body>` inherit them.
- `.frame-phone X` becomes `@media (max-width: 767.98px) { X }`, below DESIGN.md `breakpoint-tablet` (768px).
- `.frame-tablet X` becomes `@media (min-width: 768px) and (max-width: 1279.98px) { X }`.
- `.frame-tablet-landscape X` becomes `@media (min-width: 1024px) and (max-width: 1279.98px) { X }`.
- `.frame-desktop X` becomes `@media (min-width: 1280px) { X }`.
- `.frame--crop`, `.mock-*`, the bezel sizes, `.browser-chrome` (and `.frame-desktop .screen`, which sizes to it) and the static `.is-focus-ring` are mock-only and never translated.
- Media queries already inside `components.css` (the 480px Sync badge rule) apply as they are and are not repeated.
- On states: the ARIA state lives on the element the mock CSS styles. When a valid ARIA shape cannot carry the mock's attribute (a `role="radio"` cannot carry `aria-pressed`), `app.css` mirrors the mock rule's declarations for the attribute it does carry. No invented look.

A new mock rule with a `.frame-*` selector gets its translation in the same change that first renders it, and the real-browser pass checks 390, 768 and 1280 px plus a dialog.
