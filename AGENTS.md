## fasor

Releng (codename fasor): a tablet-first, offline-first web app that captures medium-voltage substation test sheets on site and generates Fasor Engenharia's FO.SERV-03 relatório as DOCX and PDF. Decided stack, no code yet: pnpm 12 monorepo with a pure zod domain kernel in `packages/domain`, React 19 + Vite 8 + Dexie in `apps/web`, Hono 4 + Drizzle + PostgreSQL 18 + pg-boss in `apps/api`, everything in docker-compose. Planning is BMAD output under `_bmad-output/`; the build contract is `_bmad-output/specs/spec-fasor/SPEC.md` with its companions.

## Policy

- The repository is public. Never copy client material from `docs/context/` or `docs/media/` (gitignored) or the third-party names, CNPJs and coordinates in `docs/concorrentes/` into tracked files; cite by path. One exception, decided by Matheus on 2026-09-21: the Porto Seguro test fixture (`packages/domain/fixtures/porto-seguro/`) and its golden documents may carry the delivered relatório's data as is (client, CNPJ, site, people, serials, coordinates, photos). See "Decisions of record" below.
- Merging a story requires `pnpm verify` green with its output pasted in the PR (lint, unit, api, Playwright `@p0`; under 15 minutes). Decided 2026-09-21.
- Everything runs in Docker through docker-compose; never install or run a service natively on the machine. The whole MVP runs locally; AWS comes only after the MVP (Epic 11).
- No story before the AWS deploy may depend on a cloud account or a paid API key; `LLM_PROVIDER` and `OCR_PROVIDER` default to `fake`. The backend never uses a personal Claude subscription.
- No emoji anywhere: UI strings, documents, mocks, code, commit messages, chat replies and agent persona prefixes. Icons are SVG sprite symbols or CSS glyphs.
- The user-visible product name is the placeholder `PRODUTO` from one constant; the codename `fasor` and Fasor branding never appear in a user-visible string, document or file name.
- `_bmad/` and `.claude/skills/bmad-*` are regenerated by the BMAD installer; overrides go in `_bmad/custom/` only.
- One branch and one pull request per story, self-approved and merged by the author; main receives only merged story PRs. There is no CI: lint and tests run locally before the merge.

## Conventions that differ from defaults

- When planning documents disagree: `source-deltas.md` wins, then the architecture spine, then `EXPERIENCE.md` and `DESIGN.md`, then `prd.md`.
- Never delete or silently rewrite a sentence in a planning document: strike the old text through (`~~…~~`), add the new one beside it with the date, and keep the reading order above.
- Code, comments, commit messages and every new document are English; the domain words below, the pt-BR UI copy and the existing Portuguese READMEs are the only exceptions.
- A story is ready to build only with acceptance criteria, a definition of ready and a definition of done written in `epics.md`; implementation stays inside what the story says.
- The deliverable is a relatório: code, routes, paths and UI say `relatorio`, never `laudo`. Identifiers are English with the domain words `relatorio`, `cabine`, `ficha`, `parecer` kept; UI copy, stored labels and the generated document are pt-BR verbatim from FO.SERV-03.
- Screens are built from the mockups with the mock's class names; `tokens.css` and `components.css` are copied unchanged into `apps/web/src/styles`; behavior comes from React Aria Components; no Tailwind, no component kit with its own theme. `DESIGN.md` and `EXPERIENCE.md` win over a mock on conflict.
- Ownership (AD-1 to AD-3, AD-13): `packages/domain` is pure TypeScript and computes every status, count, text, order and verdict once; `apps/web` renders only from IndexedDB and writes only ops into the outbox; `apps/api` applies ops and renders documents; `applyOp` is the only reducer on both sides. Nothing in `apps/*` derives a status or count from a sheet.

## Known pitfalls

- `prd.md` predates several decisions: it says "Laudo", carries wrong nameplate field counts, an export-time section-9 option and a Home "Continue" card. Each override is a row in `source-deltas.md`; never build from a PRD sentence that file overrides.
- For the Sumário and the Export dialog the prototype screens `40-relatorio-overview.html` and `73-exportar.html` are current; `key-relatorio-overview.html` and `key-export.html` are older and superseded there (MOCK-GUIDE v0.8).
- BMAD agent personas carry an emoji icon in `_bmad/config.toml`; drop it from message prefixes and from anything written to the repo.

## Where a new user-facing string goes (kept outside the managed block)

Decided 2026-09-22 (Epic 1 retro A7). pt-BR copy has three homes, and each string lives in exactly one:

- **Derived text goes in `packages/domain`.** This means anything computed from data: status words (`statusLabel`), counts and plurals (`plural`, `relatoriosCount`, `pendingSummaryText`, `rejectedText`), and composed rows (`registrationRowText`, `storageLine`, `serverHoldsText`). `apps/web` never writes a singular-or-plural choice, a status word or a rule such as "which statuses are pulled" (`isAutoPulled`) of its own.
- **Static surface copy goes in `apps/web/src/copy/pt-br.ts`.** These are headings, labels, notes, button words and fixed sentences of one surface, verbatim from the mocks or marked `// authored:`.
- **Component chrome goes in `apps/web/src/copy/ui.ts`.** These are the words a shared component owns whatever screen it is on ("Ativado", "Cancelar", the overflow trigger's label template).
